# Advanced Features

This page documents optional inputs and parameters that activate advanced modes of CardamomOT. Optional inputs are sheets of `my_project/Data/CardamomOT_inputs.xlsx` (copy of the empty template of the repository root), large numeric arrays are files of `my_project/Data/`, and per-cell information is set in `adata.obs`.

## Project directory structure (full)

```
my_project/
├── Data/
│   ├── data.h5ad                    # required
│   ├── CardamomOT_inputs.xlsx       # optional — all optional inputs (genes of interest, schedules,
│   │                                #   perturbations, timepoints, rates, model parameters...)
│   ├── reference_network.csv        # optional — prior interaction graph (sparsity mask)
│   ├── basal_init.npy / .csv        # optional — warm-start for basal parameters
│   ├── inter_init.npy / .csv        # optional — warm-start for interactions
│   ├── basal_ref.npy / .csv         # optional — regularisation target for basal
│   └── inter_ref.npy / .csv         # optional — regularisation target for interactions
└── cardamomOT/                      # generated by the pipeline
    ├── inputs/                      # export of the workbook (internal)
    ├── basal.npy                    # (n_samples, G)
    ├── inter.npy                    # (G, G)
    └── basal_ref_mask.npy           # (n_samples, G) bool — from perturbation_inference
```

## Run inputs (`Data/CardamomOT_inputs.xlsx`)

The optional inputs described in this page are cells of the workbook `Data/CardamomOT_inputs.xlsx`, filled by the user from the empty template `CardamomOT_inputs.xlsx` of the repository root (no workbook or empty cells = defaults; the pipeline never writes it and reads no text file of `Data/`). At the first use in each script (`CardamomOT.inputs.input_dir`), the workbook is exported to `cardamomOT/inputs/` (internal files, in the formats described below). Sheets: `model_parameters`, `gene_lists` (genes_queries, proliferation / death / senescence signatures, named gene lists for targets and RATE targets), `stimulus_inference_schedule` (optional `sample_id` + optional `time` column + `stimulus_k`), `stimulus_test_schedule` (optional `sample_id` + optional `time` + `stimulus_k`), `stimulus_simulation_schedule` (optional `sample_id` + optional `time` + `stimulus_k` + `STIMk` + optional `scenario`, `comment`), `perturbation_inference` (`sample_id`, `KO`, `OV`, `remove_from_inference`, `reference_sample`, `STIMk`, `RATEk`, `comment`), `perturbation_simulation` (`KO`, `OV`, `STIMk`, `RATEk`, `schedules`, `comment`), `times` (`times_inference`, `times_simulation`, `times_test`), `proliferation_rates` (`cell_type`, `net_rate_per_hour`, `sample_id`, `birth_rate_per_hour`, `death_rate_per_hour`), `population_sizes` (`time`, `population_size`), `transition_rates` (matrix). With a `time` column, schedule rows are sorted by time; without it, they follow the sorted timepoints.

**Per-sample schedules and held-out samples.** In the three schedule sheets, rows without `sample_id` (or `all`) give the default schedule of every sample; rows with a `sample_id` (a `dataset_id` of the data) replace it for that sample (e.g. an untreated control at 0). They are used per cell everywhere: mixture, OT trajectories, network inference, degradation rates, rate effects of the inference stimuli, simulations (also the per-sample `STIMk` of `stimulus_simulation_schedule` in `simulate_network_KOV`, with per-sample basals). Without a default simulation (or test) schedule, the samples keep their inference schedule. A sample marked `remove_from_inference` (True / 1) in `perturbation_inference` is held out entirely: excluded from the gene selection, `data_full` and `data_train`, all its cells in `data_test` (also with `split = full`), and `run_test` then runs `infer_test` even without a train split. `infer_test` validates it by simulating from the first-timepoint training states of its `reference_sample` (default: the largest training sample), with that sample's mixture and basal and the removed sample's `stimulus_test_schedule`, up to its last observed time (`cardamomOT/adata_sim_validation_<sample>_stim*_prior*.h5ad`; report section 6: predicted vs observed, baseline = data of the reference sample at the same times). The held-out cells of the training samples use `stimulus_test_schedule` (default: the inference schedule). A sample described in the workbook (schedule rows, KO/OV, `remove_from_inference`) but absent from the data is ignored with a warning.

**Population constraints per sample.** The population dynamics are constrained only by the sheets `proliferation_rates` (net rate per `cell_type_proliferation` type, without stimulus), `transition_rates` (matrix between the `cell_type_transition` types) and `population_sizes` (size per time, any unit), each with an optional `sample_id` (`dataset_id`; for the matrix, a column right of it); rows without `sample_id` are the default of the samples without rows of their own. A value is an information: give it for the samples that have it. The step `fit_population_anchors` (before `get_proliferation_rates`; also run when transition rates or population sizes are given) makes them consistent with the data: for each sample, a small model of growth and transitions between its types (`CardamomOT/inference/population_fit.py`: dn/dt = (diag(r) + Qᵀ − diag(Q1)) n, with r = r₀ + effects of the inference stimuli (`RATEk` on cell types) × the inference schedule of the sample over each interval) is fitted on the proportions of the types over time (noise floor 2 points, between-library variability) and, if given, on the population sizes (log size between the known times, sd 0.1; **partial anchors**: sizes at some times only, two at least): the net rates r₀ are corrected around the prescribed ones (prior ±0.002 h⁻¹, ±0.01 h⁻¹ when population sizes are given: measured sizes dominate the prescribed rates) and the transitions between types are free nuisance parameters that are **not kept**; prescribed transition rates (growth of each transition type from the corrected rates and its composition in proliferation types) are corrected the same way. A sample without rates takes the sample with rates whose rates, refitted on its proportions (and sizes), cost least (data misfit + distance to the prescribed rates); with population sizes but no sample with rates, its rates are fitted from its proportions and sizes alone (prior: its mean growth, sd 0.02 h⁻¹). A sample observed at one timepoint cannot be fitted: its rates are kept, or borrowed as they are. Without any constraint nothing is done. Result: `cardamomOT/population_anchors.json` (corrected rates, source, fit quality; transitions per sample), read by `get_proliferation_rates` (each sample anchored on its own cells; samples not in the file keep their literature estimate) and by the inference (OT: each sample its own transition matrix). The proportions alone identify only differences of rates: the absolute level comes from the prescribed rates or the population sizes. The population sizes are used there only: the growth OT pass of `fit_network` takes the mean growth of the anchored prior. Specifications for samples absent from the data are ignored with a warning. An older workbook is brought to this layout (sheet `doubling_times` removed, `sample_id` columns added) with `CardamomOT.inputs.upgrade_workbook(path)`.

**Simulation scenarios (several schedules).** `stimulus_simulation_schedule` takes an optional `scenario` column: rows without scenario give the default schedule (with its per-sample rows), rows with a scenario name give an alternative schedule for every sample (per-sample rows of a scenario are ignored with a warning), exported to `cardamomOT/inputs/simulation_scenarios.json`. The column `schedules` of `perturbation_simulation` lists the schedules simulated for each condition (`default`, scenario names, or `all`; empty = default); `simulate_network_KOV`, `check_KOV_to_sim` and the report then run / read one simulation per (condition, schedule), the scenario adding `_SCEN_<name>` to the label (e.g. a `normal` default with both stimuli on from t0, and an `alternating` scenario switching the inference stimulus and `STIM1`). Unknown scenario names and scenarios without values are ignored with a warning. With times, the rows of a simulation schedule are a step function: a value holds from its time on and applies to the simulated intervals ending at or after it (switches therefore happen at simulated times, `times_simulation`); without times, rows follow the sorted simulated times. `simulate_network` simulates the default schedule.

**Samples with their own timepoints.** Samples need not share their timepoints (e.g. 0, 12, 36, 72 h for one and 0, 12, 48, 96 h for another): they only share the network (interactions) and the degradation rates, their basals being per sample (and possibly pulled together, `constrain_basal_uniform`). The trajectories keep one row per (timepoint of the union, slot); a sample's states at the timepoints it misses are **virtual** (copies of its previous observed state, `cardamomOT/data_traj_valid.npy` = False, `obs['observed']` of the trajectory AnnData) and every interval joins **consecutive observed timepoints of its sample**: OT transport, switching times (alpha), flow-matching states, degradation rates (d1 and d0/d1, an interval of observed times feeding every inference interval it covers), growth rates (a virtual state takes the rate of its interval). Virtual states are left out of the network fits, errors, degradation inference and report comparisons. A sample starting after the first timepoint starts its trajectories from its first observed cells; its simulations start at the first timepoint (warning).

**Rates of the simulations (`times_simulation`).** The degradation rates and the scale of theta are inferred per inference interval (piecewise constant, `use_temporal_degradations`). A simulated interval takes the rates of the inference intervals it overlaps, weighted by the overlap duration (a subdivision keeps the rates of its inference interval; constant extrapolation beyond the inference times). The test set is handled the same way: `times_test` (split = train; 0 added) gives the timepoints of the test cells, which may differ from the inference ones (a time beyond `times_inference` is held out for the test only, with as many cells as a train share would have). `infer_test` transfers the rates, the scale of theta and the temporal network of the training intervals to the test intervals as above, simulates at the test timepoints, and, without `stimulus_test_schedule`, carries the inference schedule to the test times as a step function.

**Inference stimuli (`perturbation_inference`, row `sample_id = all`).** `STIMk`: possible direct targets of inference stimulus k (column k of `stimulus_inference_schedule`), as a gene list of `gene_lists` or comma-separated genes (empty: every gene). `RATEk`: effect of stimulus k on the net proliferation rate (per hour), `TARGET:delta` entries scaled by the stimulus value: on a `cell_type_proliferation` type, delta is added to its rate of `proliferation_rates`, which is then the rate **without** the stimulus; on a gene list / `GENE1+GENE2` / gene, delta × an mRNA signature score in [0, 1] (mean over the genes of log1p counts / 99th percentile; counts normalised by library size only when the transcriptome is scored). Nothing filled = one stimulus, every gene a possible target, no rate effect; the stimuli described must match the columns of `stimulus_inference_schedule`. Uses: (1) `get_proliferation_rates` adds u_k(t) · delta to the prior rate of each cell (u over the interval starting at its time; rate without stimulus kept in `obs['proliferation_net_rate_base']`); (2) `infer_network_simul` trains the proliferation MLP on the growth targets (`R_opt`) and the birth / death rates of the states, stimulus part included, with the stimulus values as inputs (`R(u, P)`): the MLP learns the effects of the stimuli on the rates, i.e. on the proliferation states of the cells; (3) the simulations only feed the MLP the schedule of `stimulus_simulation_schedule` (no stimulus effect added on top). With the inference schedule the simulations are unchanged; other schedules (stimulus removed, given later...) then also change proliferation, death and dilution through the MLP. Example (Copycat_sc): `proliferation_rates` Proliferative 0.35/24, Quiescent −0.031/24 h⁻¹ (without vincristine), `RATE1 = Proliferative:-0.00875` (−0.21 day⁻¹): with the stimulus at 1, Proliferative grows at 0.14 day⁻¹.

`model_parameters` (`parameter`, `value`, `description`; parameters grouped by use, pipeline steps first, listed with an empty value = default of `base.py`; the pipeline never modifies the workbook: to bring an older workbook to the current layout without touching its values (new columns, readme), run `python -c "from CardamomOT.inputs import upgrade_workbook; print(upgrade_workbook('Data/CardamomOT_inputs.xlsx'))"`, and copy missing parameter rows from the template of the repository root) fixes `NetworkModel` attributes for the project: every step applies it (`run_options.configure`), then its command-line options: precedence **default of `base.py` < workbook < command line**. The command line only takes the project (`-i`) and the hard-to-calibrate parameters `--stimulus`, `--prior`, `--mean-forcing`, `--force-basins`, `--temporal-basins` (those each step uses, `run_options.STEP_OPTIONS`); everything else — `CardamomOT_method` (`temporal` / `stat`, automatically `stat` without `obs['time']`), `split`, `train_rate`, `select_genes`, `build_prior_network`, `estimate_proliferation_rates`, `run_test`, `run_classical_OT`, `simulate_perturbations`, `simulate_with_proliferation`, `species`, and the step settings (`allow_depth_correction`, `depth_method`, `literature_depth`, `literature_resources`, `integrate_samples`, `ref_sample_integration`, `max_iter_softEM`, `senescence_gating`, `overwrite_degradation_rates`, `classical_ot_max_cells`, `report_*`) — is a parameter. A removed option stops the step with the name of the parameter to set. Values are cast to the type of the default; dicts/lists/None are written as Python literals. Any attribute of `NetworkModel` can be added as a row, not only the listed ones.

## Per-cell sequencing depth (`estimate_cell_depth`, first step)

Within a sample and a timepoint, cells differ in sequencing depth (capture efficiency, and cell size). A depth common to all genes of a cell acts like a hidden common regulator: it correlates all genes and can move cells between NB basins. `estimate_cell_depth.py` runs first and works on the whole transcriptome: `Data/data_complete.h5ad`, else `Data/data.h5ad` if it has at least 10,000 genes. Otherwise the depth cannot be estimated (warning, no correction). Raw counts are taken from a counts layer if `X` is log-normalised; obs names close to the expected ones are recognised (see `harmonize_obs`).

**Diagnostic**, within homogeneous groups (sample, time, cell type; cell types too small within their (sample, time) pooled), on the 1000 most variable reference genes expressed in > 5% of the cells: spread of the depth factor (q95/q05), share of the within-group gene-pair correlation explained by the log depth, share of the genes whose NB modes at the mixture initialization are closer than the depth spread, the extrinsic noise Var[c]/E[c]² of each group (Fang & Pachter: mode of the normalized covariances, refined on the group's Poisson genes; the strength of the factor common to all genes, technical or biological — Copycat_sc: 0.17–0.64, about twice higher in proliferating than in quiescent cells), and the correlation of depth with `obs['doublet_score']` if present (doublets must be filtered upstream: a depth factor does not correct them). The correction is recommended when more than 50% of the correlation is due to depth or more than 50% of the genes have modes closer than the spread. Outputs: `cardamomOT/depth_diagnostic.csv` (per group) and `depth_diagnostic.json` (global indicators and decision), shown in section 0 of the final report.

**Depth factor.** If recommended and `model.allow_depth_correction = True` (default), the factor of `model.depth_method` is written to `obs['depth_factor']` of `Data/data.h5ad` (`X` untouched) and follows into `data_full/train/test`. **Use:** the NB mixture, gene selection, network steps and simulations use it only if `model.use_depth_factor = True` (default `False`: s_i = 1, an existing factor is kept but ignored; report page 0 states it). **Computation:** with `model.compute_depth_factor = False` (default `True`), `estimate_cell_depth` computes nothing: it reads and summarises an existing `obs['depth_factor']`, never removes it, and leaves the previous diagnostic files. Methods (`CardamomOT/inference/depth_methods/`, interface `compute(X, lib, groups, **params) -> s`, parameters in `model.depth_method_params`, custom ones in `<project>/depth_methods/<name>.py`), each with a `reference` (groups = (sample, time), with the cell type if `depth_by_cell_type`):

- `'poissonian'` (default) — Fang & Pachter (bioRxiv 2025, [pachterlab/FP_2025](https://github.com/pachterlab/FP_2025)): the extrinsic noise s is the mode of the normalized covariances Cov(Xa, Xb)/(E[Xa]E[Xb]) between genes of mean > 0.1; "Poisson" genes are those whose 95% bootstrap interval of normalized variance (Var − E)/E² contains s (re-estimated on them until stable); s_i is the Poisson MLE of the cell size on the Poisson genes. `reference`:
  - `'sample_any'`: within each group (time-resolved), s_i relative to the group means (mean 1 per group): the extrinsic noise differs between groups (Copycat_sc: 0.4–0.6 for proliferating cells, 0.2–0.34 for quiescent ones), and depth differences between the groups (separate libraries) are not corrected;
  - `'sample_all'`: on the cells of the whole sample at once, as in the paper (one population), s_i relative to the sample means: the pooled heterogeneity leaves few Poisson genes (Copycat_sc: 37–60 per sample, against thousands per time), hence noisy factors (within-time rank correlation 0.83 with `'sample_any'`);
  - `'sample_pairwise'` (default): the `'sample_any'` factors (precise within a time) times a scale λ^α per group: for each pair of groups of a sample, r = median over the genes Poisson in both of the log ratio of their means (robust to a minority of genes changing between them), then log λ fitted by least squares on log λ_t − log λ_t′ = r (weights = shared genes, mean of log λ 0 in the sample; with every pair, the mean of the ratios to the other groups); `alpha` in [0, 1] (default 1) = share of the correction (0 = `'sample_any'`). It corrects the depth differences between the libraries of the times, but so would it a global change of mRNA content (no spike-in to tell them apart). Copycat_sc: median 636 / 2575 / 167 shared genes per pair (RD / RMS2 / RMS9), λ 0.73–1.31 (RD), 0.92–1.18 (RMS2), 0.90–1.16 (RMS9), following the library sizes; within-time ranking of the cells unchanged.
- `'group_median'` — s_i = library of the cell / median library of its population: `reference='sample_any'` (default, its group) or `'sample_all'` (its whole sample: standard library-size normalisation). Libraries of `group_median` exclude the 50 most expressed genes.

**Groups of the estimation.** s_i is estimated within (sample, time) groups by default (`model.depth_by_cell_type = False`); the diagnostic always uses (sample, time, cell type). Estimating within cell types is circular: cell types derive from expression, and normalising each type to its own median depth pulls the intermediate cells towards their type and artificially separates the types (Copycat_sc, proliferating vs quiescent: silhouette 0.18 without correction, 0.36–0.39 with (time, cell type) groups, 0.23–0.25 with (time) groups, 0.24 with a global `normalize_total`). The price is that depth differences between cell types of a sample and time (e.g. larger proliferating cells) are partly treated as technical.

**Use of s_i.** Counts are modelled as NB(k, c / s_i): they stay integers, and k (basins, kon) and c are those of a cell at the reference depth. Gene selection: Gandrillon scores, highly variable genes and the OTVelo network on x / s_i (BUB entropy on the rounded values), NB floor with the depth-aware initialization. Mixture (`infer_mixture`, test classification, multi-sample integration, which keeps each cell's depth): depth-aware likelihood, initialization and M-steps. Trajectory inference: counts at the reference depth x / s_i. Simulations run on proteins only; the NB counts of check scripts and the report are drawn with the s_i of the real cell behind each trajectory state (`data_traj_real_idx.npy`), simulated trajectory j taking that of state j at the nearest inferred time. Proliferation scoring already normalises each cell (`normalize_total`).

## Gene selection (`select_genes`, `genes_queries` (sheet `gene_lists`))

`split_dataset.py` first writes `obs['split']` in `Data/data.h5ad` (`full` for every cell with `split = 'full'`; `train` / `test` / `unused` with `split = 'train'`; `test` for the samples with `remove_from_inference`), then `select_genes.py` selects the genes on the `train` (or `full`) cells only, so that the test cells do not leak into the selection, and writes `data_full` (cells of the inference samples), `data_train` and `data_test` restricted to the selected genes. With `select_genes = False`, `select_genes.py` keeps all the genes of `Data/data.h5ad`. With `select_genes = True`, the genes of the model are selected from the whole transcriptome (raw counts) within a budget of `model.num_max_genes = 100` genes (`CardamomOT/inference/gene_selection.py`):

1. **Gene universe**: protein-coding (`gene_type`/`gene_biotype` column of `adata.var` if present, else by name), non mitochondrial/ribosomal genes expressed in at least 3 cells.
   **Variability floor**, applied to every gene, queries included (a gene that the NB mixture will fit with a single basin is useless to the model): (i) the largest BUB-entropy change between consecutive timepoints (Gandrillon MDE, already computed for the entropy genes) must reach `min_entropy_change = 0.1` bit; (ii) for the candidate terminals, then on demand for each gene the Steiner selection would add (a failing gene is removed from the graph and the selection redone; most network genes are never checked), the **initialization of the NB mixture** — the same as in `infer_mixture`, on `batch_size_mixture` cells per timepoint: one mode per timepoint and per cell type with a common rate, the most diverse labelling kept — must separate its extreme modes by `min_nb_separation = 0.15`, the separation of two NB modes `kmin < kmax` with rate `c` being `(kmax − kmin) · sqrt(2 / ((kmin + kmax)(c + 1)))` (mean gap over the pooled standard deviation). On Copycat_sc, the ~100 nearly unexpressed genes previously picked as closure regulators have MDE ≤ 0.04 and separation ≤ 0.06, against ≥ 0.15 and ≥ 0.2 for expressed genes. On RD136 the entropy floor keeps 7013 of 11082 genes; the NB check costs ~4 s.
2. **Terminal genes**, chosen among the high-entropy genes (below; the entropy changes between consecutive timepoints already carry the time information, so there are no timepoint groups) by a **round robin over the cell types** (`cell_type_selection`, else `cell_type`), each against the rest with Wilcoxon scores on log-normalised counts (scanpy): each cell type in turn takes its best candidate not yet taken, the genes significantly DE in it (adjusted p < 0.05, positive score) first, so that all cell types are covered (without cell types: by decreasing entropy change):
   - at most `n_query_genes = 20` genes of `genes_queries` (sheet `gene_lists`) (one per line or comma-separated);
   - the fate drivers of the classical OT (`n_driver_genes`, round robin over the fates);
   - at least `n_entropy_genes = 20` genes (raised to two per cell type if lower) among the **entropy genes** of O. Gandrillon's workflow ([From_fastq_to_CardamomOT](https://github.com/ogandril/From_fastq_to_CardamomOT), `CardamomOT/inference/gandrillon.py`): genes in the top `n_top_entropy = 200` of each transition for the 1-D Wasserstein distance of their counts between consecutive timepoints divided by the standard deviation of the gene over the two timepoints (KD, scale-free: the raw distance grows with the expression level and favoured the strongly expressed genes), and in the top 200 for the absolute change of their discrete entropy (MDE), estimated per timepoint with the BUB estimator (Paninski 2003; Python port identical to the R code, on at most `n_cells_entropy = 1000` cells per timepoint).

   `n_query_genes + n_entropy_genes` must be lower than `num_max_genes`: the rest of the budget goes to the paths.
3. **Coarse global network** on the `n_hvg_selection = 3000` most variable genes (all candidate terminals always kept), with the stimulus as a source node, built by `model.network_method` (see below).
4. **Edge probabilities**: the same method is run on permuted data (each gene permuted independently across cells, removing every gene–gene dependence), and each edge gets the probability of being real `w = 1 − q`, `q` being the tail FDR of its `|C|` against the null (`P_null(|C| ≥ x) / P_real(|C| ≥ x)`, made monotone). With `null_network = 'hybrid'` (default), gene-to-gene edges are judged against a permutation **within each (sample, time)** — an edge must rest on cell-to-cell co-variation beyond shared temporal trends, which CardamomOT explains by the stimulus and the basals —, and stimulus edges against a permutation **across all cells** (a stimulus can only explain trends); `'within_time'` or `'all_cells'` use one null for both. Edges with `w < min_edge_prob = 0.05` are dropped. With `literature_selection = True` (default, whatever the prior), the gene-to-gene probabilities are then reweighted by **literature feasibility** (see [Prior interaction network](#prior-interaction-network-build_reference_network)): with the odds of `w` multiplied by a likelihood ratio LR = P(feasible | edge) / P(feasible | no edge), estimated on the covered pairs with `w` as soft labels (so a literature that agrees little with the data weighs little; `literature_weight = 1` is an exponent on LR, 0 = data only). Pairs the literature does not cover and stimulus edges are unchanged, and `w = 0` stays 0: the literature reweights the data edges, it does not create any (RD136, depth 3: LR 1.58 for feasible, 0.87 for infeasible pairs; 9 of the 100 genes change).

5. **Prize-collecting Steiner selection, anchoring**: a set of genes, not a tree. Edges `i → j` (the `k_in_steiner` most probable regulators of each gene, the `k_stim_steiner` most probable targets of each stimulus, ties broken by `|C|`) are real with probability `p = w · edge_prior` (`edge_prior = 0.9`: every extra step costs something). The **anchoring** of a selected gene is the probability that it is reached from the stimuli through the selection, a noisy-OR over all its selected regulators, `a_j = 1 − Π_i (1 − p_ij a_i)` (fixed point): every edge between selected genes counts, several paths add up and loops are allowed, unlike in a tree. The most probable path (path probability × anchoring of its start) to each required terminal not yet anchored is added, cheapest first; it may start from any anchored gene and go through other terminals. A terminal left without incoming edge after filtering keeps its best one (probability floored at 0.001, used only as a last resort); required terminals that still cannot be anchored are kept.
6. **Prize-collecting growth (regulatory closure and redundancy)**: the goal is that CardamomOT on the selection approaches the full-transcriptome network restricted to it, which fails when important regulators of the selected genes are missing (hidden common regulators create spurious edges, hidden mediators remove links), and is fragile when a terminal hangs on a single path. Each gene outside the selection is worth the expected number of real regulations it brings to the selected genes (sum of its `w ≥ min_edge_prob` towards them; a missing regulator biases the inference even for a gene that has others) plus the anchoring it brings to the terminals, `Σ_t a_k p_kt (1 − a_t)` (new or redundant paths from the stimuli). The gene worth the most is added, repeatedly, while it is worth at least `closure_min = 0.5`, the cost of a gene. The log reports the share of the probable regulation entering the selected genes that comes from inside the selection.
   Genes perturbed in sheet `perturbation_simulation` and sheet `perturbation_inference` are always selected (required terminals, exempt from the variability floor), so that the in-silico perturbations target genes of the model. Gene lists accept `#` comments.
   **Proliferation markers** (`n_proliferation_markers = 10`, with `protein_dilution` or `simulate_with_proliferation`): genes always selected too, so that the proliferation MLP R(P), which only reads the proteins of the model, can tell the proliferation states of the cells apart. Half of them best separate the labels of `cell_type_proliferation` (one indicator per label, taken in turn; e.g. quiescent / proliferative), the others best predict the prior net rate of the cells (`obs['proliferation_net_rate']`, from `get_proliferation_rates` or the anchors per cell type): net-rate markers alone are mostly cell-cycle genes, which follow the labels less well. Genes are ranked by |correlation| of log1p(counts, / depth factor with `use_depth_factor`) with each target within (sample, time) groups (no batch nor time trend), mitochondrial and ribosomal genes left out, and kept greedily when correlated below 0.8 with those already kept (one gene per co-expressed module would otherwise be repeated). Without a per-cell rate: indicator of the most proliferative cell type (highest rate in `proliferation_rates`, else a name containing "prolif") of `cell_type_proliferation`, else `cell_type`; with a single target, all the markers go to it. With `select_genes_per_condition`, per condition. The report (proliferation, prior vs learned) gives the fit of the MLP on its target and how well the model's proteins separate the proliferation cell types.
7. **Budget saturation**: if budget remains, the next genes of the two round robins (queries and entropy genes alternately) are tried, each with its most probable path from the anchored genes, and added if they fit.


**Several samples (`dataset_id`).** The selection runs before the integration of the samples, so every dynamic signal is computed **within each sample**, a difference between samples (cell line, batch) never being taken for a dynamics: entropy changes (KD/MDE on the transitions of each sample), NB basins at initialization (best separation over the samples: a gene with two basins in one sample is useful to the per-sample mixtures) and Wilcoxon groups of the round robin ((sample, time) and (sample, cell type) against the rest of the sample) — candidates are the **union** over samples; highly variable genes with the sample as `batch_key`; **one network per sample** with its own nulls and its own stimulus schedule (per-sample rows of `stimulus_inference_schedule`), turned into edge probabilities W_s, then combined according to `sample_network_combination`: `'consensus'` = W = Σ w_s W_s with w_s ∝ cells × transitions of the sample (the network is shared by the samples: an edge must be supported in several of them; raw network amplitudes are not comparable between samples, probabilities are), `'any'` = probabilistic OR W = 1 − Π (1 − W_s) (an edge supported in one sample is a candidate: independent condition networks), with a **closure balanced over the samples** (each step serves the sample whose regulation of the selection comes least from inside it, with the gene bringing it the most probable regulation, at least `closure_min` in that sample). `'auto'` (default) = `'any'` with ≥ 2 network conditions and `network_condition_pen = 0`, else `'consensus'`. With a consensus, an edge supported in a single sample cannot pass 0.6 (Copycat_sc, weights 0.27/0.57/0.17: 1450 edges ≥ 0.6 in one sample, 12 in two, 0 in three, hence 6 edges ≥ 0.6 inside the selection); with `'any'` and the balanced closure, inside-regulation shares of 41/40/40% per sample (consensus 25/62/31%). Literature and Steiner selection then work on the combined W; `gene_selection_report.csv` gives, per gene, the samples in which it has an edge inside the selection (`edge_samples`, exponents of the gene page of the report). Samples measured at a single timepoint add no dynamics (but count for the NB check with cell types); samples marked `remove_from_inference` are excluded. With one sample nothing changes.

Without time information, there is no network: the required terminals are selected. Outputs: `cardamomOT/gene_selection_report.csv` (each selected gene, its role — query, entropy, steiner, regulator —, the group that picked it, whether it was required, its anchoring to the stimuli (`anchoring`, `anchored`), its best anchoring regulator (`anchor_parent`) and the probability of that edge, its regulators (`is_regulated_by`) and targets (`regulates`) inside the selection — every edge of the global network with probability ≥ `selection_edge_prob = 0.6` that is literature-feasible (path of at most `literature_depth` edges, last one TF → target; `*`: pair not covered by the literature, kept as in the prior), stimuli included —, `connected` (at least one such edge), and the groups where it is significantly up, adjusted p < 0.05) and `cardamomOT/global_network.npz` (`C`, the null networks `C_null` (gene edges) and `C_null_stim` (stimulus edges), edge probabilities `W` (and, with the literature, `W_data` before reweighting and the feasibility `F`), `genes`; stimuli first), and with the literature `cardamomOT/ref_network.csv`, the literature prior of the selection (below).

### Global network methods

`model.network_method` names the method building the coarse network; `model.network_method_params` (dict) overrides its parameters. Built in: `'otvelo_granger'` (default), `'wot_granger'` and `'otvelo_corr'` (`CardamomOT/inference/global_networks/`). `'otvelo_corr'` — OTVelo-Corr (Zhao et al., *PLOS Comput Biol* 2024; reimplemented from [sandstede-lab/OT-Velocity](https://github.com/sandstede-lab/OT-Velocity), identical to it up to machine precision): entropic fused Gromov–Wasserstein couplings between consecutive timepoints on log(x+1) counts, gene velocities through the couplings, time-lagged correlation of the velocities; one network per sample, averaged with cell weights. Parameters: `n_cells` (500 per timepoint), `n_pcs` (50, coupling costs on principal components), `eps` (0.01), `alpha` (0.5). `'otvelo_granger'` (OTVelo-Granger, eq. 2.7–2.8 of the same paper, identical to the reference code when all regulators are candidates): for each interval, an elastic net regresses the velocities of each gene at t+1 on the velocities at t (mapped through the coupling) of its `k_candidates = 50` strongest OTVelo-Corr regulators, its own past and the stimuli; coefficients summed over intervals. Much sparser than Corr (indirect and confounded correlations removed). Extra parameters: `k_candidates`, `l1_ratio` (r = 0.5, the paper's value), `en_alpha`, `scale` and `stim_weight`. The paper's penalty λ = 1 was calibrated on ~10 genes: the regressors are velocities averaged through the coupling, which shrink as the coupling gets diffuse (PCA of thousands of noisy genes), so that with λ = 1 almost every coefficient is null on a whole-transcriptome universe (Copycat_sc, 5078 genes: 0.001% of the pairs, 98% of the genes without any edge). Hence: regressors and responses scaled to unit RMS per interval (`scale = True`; not centred, the mean velocity being the stimulus effect), so that λ acts as a correlation threshold; stimuli penalised `stim_weight = 10` times less (they play the role of the intercept, otherwise absorbed by the genes with a mean velocity at low λ); `en_alpha = 'auto'` = min(1, sqrt(50 / G)), the paper's value up to 50 genes. On Copycat_sc (edges with w ≥ 0.6 against the hybrid null): median in-degree 3 for 50 genes, 5 for 200, 13 for 1000, 21 for 5078 genes, no isolated gene from 200 genes on, 65–90% of the genes targeted by the stimulus. For comparison `'otvelo_corr'` gives 9 significant edges per gene on 5078 genes, but concentrated on hubs: median in-degree 0 and 70% of the genes without any edge.

## Classical OT (`run_classical_OT`, default True)

Before CardamomOT, `run_classical_OT.py` runs a Waddington-OT / moscot-style analysis on **every gene** and the train cells (all the cells with `split = 'full'`), per sample (`CardamomOT/tools/classical_ot.py`, no external package): log1p(counts / `depth_factor` if computed, else `normalize_total`), genes expressed in ≥ 10 train cells, PCA (50 components) fitted on the train cells; between consecutive timepoints of each sample, entropic unbalanced OT (scaling algorithm) on squared Euclidean distances divided by their median, WOT defaults ε = 0.05, λ1 = 1 (source relaxed: growth), λ2 = 50 (target nearly strict), source marginal ∝ exp(r Δt) with r = `obs['proliferation_net_rate']` if present. At most `classical_ot_max_cells = 5000` cells per (sample, time) are transported.

Outputs (`cardamomOT/classical_OT/`): `transitions.csv` (cell-type flows, fate and ancestor probabilities per sample and interval; `sample = all`: pooled, each sample of mass 1), `fate_genes.csv` (per cell type: genes up in its **immediate ancestors** against the ancestors of the other cells — coupling weights pooled over intervals and samples —, and genes up in the cell type against the other cells; weighted Welch t, log fold change, ranks, `top10_both`), `velocity.npz` and `couplings.npz`. Velocities: barycentric, (mean of the descendants − x) / Δt, or (x − mean of the ancestors) / Δt at the last time, in the PCA space of the UMAP of `Data/data.h5ad` (`cardamomOT/umap_data.npz`); the other cells (test, unused, beyond `classical_ot_max_cells`) by Gaussian-kernel regression over their 30 nearest transported cells in the PCA space of the transport, within their sample and timepoint.

Report: a Sankey of the cell-type flows across every timepoint (a link leaves its node with width ∝ the fate probability and reaches its target with width ∝ the ancestor probability) with the table of the top-10 fate genes, the velocity field on the UMAP of every cell, then a **teaser** comparing it with the velocity field of CardamomOT on the same UMAP. CardamomOT's velocities come from the final soft couplings of its trajectories (`cardamomOT/couplings.npz`, written by `infer_network_structure`: same costs, marginals and regularisation as the trajectory OT, computed once with the final network in the growth pass, sparse — top 50 targets per state —, indexed by the rows of `data_<split>.h5ad`); the cells never reached by the trajectories and those outside `data_<split>` get a Gaussian-kernel velocity in the space of the model mRNAs (log1p, counts / `depth_factor` if computed).

## Report visualisation (`embedding_method_visualization`, `cell_depth_for_representation`, `classifier_method`)

These parameters only change the figures of the report, never a computation (the depth factor of the mixture, of the network inference, of the classical OT and of the kernel regressions of the velocities follows `use_depth_factor`):

- `embedding_method_visualization` (`'umap'` default, `'pca'`, `'phate'`): every 2-D embedding of the report. One mRNA embedding is learned on the observed cells and every model output (trajectories, NB mixture, network modes, simulations, perturbations, test and validation, learned dynamics) is projected onto it; one protein embedding is learned on the protein trajectories and the simulated proteins are projected onto it (the data page of the whole transcriptome and the integration diagnostic keep their own embeddings). PHATE (`pip install phate`) suits trajectories; points not used to fit it (perturbations, test cells) are placed by a kNN extension (inverse-distance mean of the coordinates of their 10 nearest fitted points), UMAP and PCA use their own `transform`.
- `cell_depth_for_representation` (default `True`): every mRNA shown (data UMAP, generative model, perturbations, test and validation, learned dynamics), and the counts on which the cell-type classifiers are trained and applied, are counts / depth factor (log1p for the embeddings), the **same transformation for the data and the model**: the observed cells and the reference trajectories are divided by their depth factor, the NB draws of the models are taken at the depth of the cell they mimic and divided by it (`obs['depth_factor']` of the draws, written by `check_mixture_to_data`, `check_sim_to_data`, `check_KOV_to_sim` and `infer_test` when the run uses depth factors). Draws and data thus carry the same noise: comparing counts / s with draws at the reference depth would make the model look compressed (x / s is more dispersed than a draw at s = 1 when s varies). The depth no longer drives the gene-pair correlations, which then measure what the modes (and the network) explain; the report gives, next to them, the ceiling of a model with these modes and genes independent given them (reference shuffled per gene within sample, time and mode). With `False`, raw counts, and model draws at the depth of the cells they mimic. Without a depth factor, both are the same.
- `classifier_method` (`'logistic'` default, `'random_forest'`): classifiers of the cell types of the model outputs (one per sample, trained on the observed cells, in the representation above). The random forest uses the counts and fine co-expression; the logistic regression (standardised log1p counts, multinomial, balanced class weights, L2 penalty C chosen by 3-fold cross-validation on the training cells of the sample, balanced accuracy, every time pooled) relies less on co-expression, which models with genes independent given their state cannot reproduce. Balanced weights raise the recall of the rare types but also their predicted share: the model outputs are compared with the data labelled by the same classifier, not with the annotated shares. Cell-type proportions show both **Data** (annotated labels) and **Data (predicted)** (out-of-fold predictions on the observed cells, 3 folds stratified by sample and type: what the classifier says of cells it has not seen, the reference of the classified model stages); the Reference stage takes the out-of-fold label of the real cell behind each state (`obs['real_idx']` of `adata_rna_traj_<tag>`), and test or held-out cells are labelled by the classifier. The notebooks (`check_cell_types_full(p, stim, prior)`, `check_cell_types_mixture(p)` in `utils/compare_cell_types.ipynb`) read the same stages (`read_model_stages`) with the same classifier (`project_classifier`: data of the run, options of the project) and write nothing. The page "cell-type identity in the NB mixture" always shows both.

`./run.sh <project> [hard options] --report-only` (or `cardamomot pipeline -i <project> --report-only`) rebuilds the report with the current visualisation parameters: it reruns every check script of the run (`check_mixture_to_data`, `check_sim_to_data`, `check_test_to_train`, `check_KOV_to_sim`, as configured), `run_classical_OT` if its outputs are missing or from an earlier version, then the report; the inference steps (including `infer_test`) are never rerun.

`./run.sh <project> [hard options] --from <step>` (or `cardamomot pipeline -i <project> --from <step>`) resumes the pipeline at `<step>` (e.g. `infer_network_simul`), reusing the outputs of the earlier steps.

**`'wot_granger'`**: the same Granger regression (unit-RMS scaling, `stim_weight`, `en_alpha = 'auto'`) through the **couplings of the classical OT** (`run_classical_OT`, which runs before `select_genes`: every gene, train cells, growth) instead of the OTVelo couplings: a gene regulates another when its velocity at t predicts the velocity of the other at t + 1 along the inferred trajectories (regulators and targets of the genes of interest). The couplings are fixed: the null networks are regressions through the same couplings on the permuted cells. Parameters: `n_cells` (2000 per time, the cells carrying most coupling mass first), `k_candidates`, `en_alpha`, `l1_ratio`, `scale`, `stim_weight`.

**Fate drivers** (`n_driver_genes = 20`, terminals of the selection after the queries, before the entropy genes): `run_classical_OT` chains its row-normalised couplings backwards to get, for every transported cell, the probability that its descendants at the last time of its sample belong to each cell type (`classical_OT/fate.npz`); a driver of a fate is a gene whose expression correlates with that probability **within each earlier timepoint** (no time confounding), over the cells not yet of that type (priming rather than markers), Fisher-combined over the timepoints, BH q ≤ 0.05 (`classical_OT/fate_drivers.csv`). As co-expressed modules (e.g. the cell cycle) dominate several fates, drivers are taken in round robin over the fates a gene being redundant when its expression correlates (|r| ≥ 0.3) with **two** drivers already taken at once (column `representative`): each co-expressed module keeps two genes, and a gene linked to a single one stays (finer signals). They are subject to the gene universe and the variability floor like the other terminals (role `driver` in `gene_selection_report.csv`). Budget: n_query + n_driver + n_entropy (+ perturbed genes) must leave room for the Steiner paths and the closure.

**Entropy pre-selection** (`entropy_preselection = True`): the queries, the fate drivers and every gene of the network (hence of the Steiner paths and of the growth) are taken among the entropy candidates (Gandrillon KD & MDE, top `n_top_entropy` per transition) only; the perturbed genes are always kept. The listed stimulus targets (`stimulus_targets`) are possible interactions only, they never enter the universe: a stimulus whose listed targets are in the data but none in the network has no stimulus edge (none in the data: unconstrained).

**Fate prediction** (in `selection_preservation.json`, all network methods): cross-validated R² (5 folds, ridge) of the fate probabilities of the classical OT on every gene, predicted from the expression at t of the selected genes with the timepoint as covariate (cells before the last time), against the time only, random gene sets of the same size, and every gene (PCA). The classical OT on every gene is the common reference of every selection method.

**Trajectory preservation of the selection** (`cardamomOT/selection_preservation.json`, written by `select_genes` when `run_classical_OT` was run; shown on the gene-list page of the report): the classical OT is rerun on the selected genes only (same cells, preprocessing and parameters) and compared with the one on every gene by the weighted cosine of the velocities of the transported cells in the full PCA space (1 = same directions) and the mean Jensen-Shannon distance of the cell-type fate distributions (0 = same transitions), with random gene sets of the same size as baseline.

## Prior interaction network (`build_reference_network`)

The gene selection (`select_genes = True`, `literature_selection = True`, `prior_network_pen = 0`, `build_prior_network = True`) writes the literature prior of the selected genes to `cardamomOT/ref_network.csv`. For a gene list chosen otherwise, build it with:

```bash
cardamomot step build_reference_network -i my_project   # literature_depth, literature_resources, species
```

Both use `CardamomOT/inference/literature.py`. Literature: OmniPath post-translational interactions (directed) and TF → target interactions (CollecTRI, plus less curated resources by default, see below), downloaded once (organism detected from the gene names, or `--species`) and cached in `~/.cache/cardamomot` (`CARDAMOMOT_CACHE`). A CardamomOT edge A → B means that protein A changes the transcription of B, possibly through unobserved intermediates, so it is **feasible** when the literature holds a path A → … → B of at most `depth` edges (`literature_depth = 3`) whose **last edge is transcriptional** (a signalling-only path changes the activity of B, not its mRNA) and whose intermediates are **not among the selected genes** (a path through an observed gene is already a chain of the network). No sign and no length weight through unobserved intermediates (the effect looks direct): such edges get 1. When every path goes through `k ≥ 1` selected genes, the edge gets `1/(k+1)` instead of 0 (the network may still need a direct edge; a missing edge is the costly error, since with `--prior 0` it can never be inferred, whereas CardamomOT's sparsity removes inactive allowed edges). Covered pairs without any path get 0, and pairs the literature does not cover (regulator absent from OmniPath, or target without any TF → target edge) a neutral 1, so that understudied genes are not penalised. On RD136 (3000 genes): 69% of the genes covered as regulators, 49% as targets; 3% of the covered pairs feasible at depth 2, 18% at depth 3, 41% at depth 4. `literature_resources`: `'extended'` (default: OmniPath and CollecTRI + PathwayExtra, KinaseExtra, LigRecExtra, DoRothEA A–D, TFtarget, 4× more edges) or `'core'` (OmniPath + CollecTRI). Extended does not loosen the prior: it covers almost all genes (97% vs 66% of the targets of a 100-gene selection), so fewer pairs keep the neutral weight (100-gene RD136 selection, depth 3: 61% of the edges allowed with core, 53% with extended; depth 4: 71% and 68%).

**Selection and prior built together (hard prior).** With `select_genes`, `literature_selection`, `build_prior_network` and a hard prior (`--prior 0`, or `prior_network_pen = 0` in the workbook / `base.py`), the gene budget is no longer `num_max_genes` but the largest number of genes whose literature prior leaves at most `model.max_free_params = 10000` free network parameters (allowed gene → gene entries, self-regulation included, + stimulus → gene edges), found by bisection on the Steiner budget (RD136: 132 genes for 10k, 93 for 5k; the extra budget goes mostly to closure regulators). Otherwise the budget stays `num_max_genes`; the selection still uses the literature whenever `literature_selection = True` (without it, the literature is not queried at all). The selection writes the prior only in this hard-prior case, and the pipeline then skips `build_reference_network`; in every other case with `build_prior_network`, `build_reference_network` builds it after the selection, with the same parameters (`literature_depth`, `literature_resources`). With `build_prior_network = False`, a `ref_network.csv` of an earlier run is removed by the selection.

The number of free interactions (`G² ×` allowed share, printed by both scripts) is the trade-off with `--prior 0`: for 5–10k free network parameters, about 95–135 genes with the defaults (extended, depth 3, ~53% allowed), 150–210 with extended at depth 2 (~22%), 90–130 with core at depth 3 (~60%).

`cardamomOT/ref_network.csv` is a gene × gene interaction matrix (a user matrix can also be given as `Data/reference_network.csv`). The `--prior` parameter then controls how strongly edges absent from this prior are penalised. Values are signed weights: `0` marks an absent edge, `0 < |v| ≤ 1` leaves the sign free but makes the edge cost `1/|v|` more than a sure edge (in both the inference and the refinement, without reducing its maximal strength), and `|v| > 1` marks a sure edge whose sign is forced (`> 1` activation, `< -1` inhibition). Literature priors are 0 or 1, so they never force a sign.

| `--prior` value | Effect |
|---|---|
| `1.0` (default) | No penalisation — all edges equally possible |
| `0.5` | Soft penalisation — absent edges discouraged |
| `0.0` | Hard mask — only edges present in the prior are allowed |

**The same `--prior` must reach both steps** — it constrains *inference* in `infer_network_structure` and the *simulation reference network* in `infer_network_simul` (and the file tags of the checks and report). The pipeline forwards it to all of them.

```bash
# Easiest: build_prior_network = True in the workbook (literature_depth = 3 by default; 1 = faster), then
cardamomot pipeline -i my_project --prior 0.5

# Or step by step — same --prior everywhere:
cardamomot step infer_network_structure -i my_project --prior 0.5
cardamomot step infer_network_simul     -i my_project --prior 0.5
```

## Custom stimulus schedule (sheet `stimulus_inference_schedule`)

By default one stimulus is `0` at the first timepoint and `1` at all subsequent ones. To define a custom schedule, fill the sheet: **rows = timepoints** (optional `time` column) and **columns = stimulus channels** (`stimulus_1`, `stimulus_2`…):

| time | stimulus_1 | stimulus_2 |
|---|---|---|
| 0 | 0 | 0 |
| 24 | 1 | 0 |
| 48 | 1 | 1 |

- Values between 0 and 1 are allowed (partial stimulus strength).
- If fewer rows than timepoints are provided, the last row is repeated.
- Simulations read sheet `stimulus_simulation_schedule` (one row per simulated time): first the columns of the inference stimuli (e.g. a novel protocol), then one column per perturbation stimulus STIM1, STIM2… of `perturbation_simulation`. Without it, the inference schedule is used and the perturbation stimuli take their default (0 at the first time, 1 after).

The `--stimulus` parameter controls how strongly the stimulus regulates genes in the inferred network:

| `--stimulus` value | Effect |
|---|---|
| `1.0` (default) | Full stimulus influence |
| `0.0` | Stimulus has no regulatory influence |

## NB mixture initialization (times and cell types)

Each gene's mixture (`infer_mixture`) starts from one NB mode per timepoint with a common rate, the lowest and highest modes giving the initial extreme basins. When the cells carry a cell type (`cell_type_selection`, else `cell_type`), the same is done per cell type, and the labelling whose extreme modes are the most separated (groups with fewer than 50 cells or 5% of the cells left out: their extreme modes may be chance) (NB separation, see gene selection) gives the initial `kmin`, `kmax` and `c`; the hard EM (CEM: mass-constrained assignments, masses per time preserving the mean of each time) then fits the modes freely (bounding them by the means of the extreme groups put a gene off at its earliest time in a low mode near 0 at every time, and overpredicted its zeros). A soft EM with masses per time (`max_iter_softEM` iterations, default 100; 0: CEM only) then refines the CEM: the modes are shared by the times, their weights are not, and the posteriors are not truncated (the hard assignments overestimate the rate c and put the low mode too low); the basins are reassigned with the refined modes, under the same masses preserving the mean of each time. Genes varying between cell types more than over time (e.g. cell-cycle genes in an asynchronous population) thus get distinct basins (Copycat_sc, MKI67: one mode with the temporal initialization, two with the cell-type one). Without cell types the initialization is unchanged.

**Hard or soft basins (`one_hot_probas`).** The basins of `fit_network` come from the costs −log posterior + (1 − w_prob)·KL(τ_m ‖ σ) per cell and mode, the network term being the log-likelihood of the mode under the sigmoid (τ_m the sigmoid target of mode m, σ that of the predicted kon, the cross-entropy of the network fit), weighted by w_g = 1 − k_low/k_high so that weakly separated genes keep a weak network term. The basins are updated from the first iteration, the weight of the network term growing from 0 (1 − max(0.96^(n−1), 0.1)). In both cases, the basin of each cell is the mass-constrained assignment (EMD) of these costs under the mode masses of the mixture (per time with `temporal_basins`; the initial one without the network term), and its mode forces the trajectories. With ordered levels, this assignment ranks the cells by their posteriors and gives them the quantiles of the distribution of the modes: the forcing has the right distribution of modes and the right ranks (the triple-goal estimate of Shen and Louis, 1998), is deterministic, and never forces an uncertain cell at an intermediate level for a lack of information, whereas the expected modes have a too narrow distribution and draws add noise and attenuate the network more. With `True`, the network is fitted on these basins: a classification EM. By default (`False`), the posteriors updated by the network are the rows of the entropic OT of regularization 1 under the same masses (posterior × one factor per mode, so that the masses are the mixture ones), with the network term at full weight, κ_g·KL(τ_m ‖ σ), without the ramp nor w_g: the soft E-step of the EM. A cell whose counts do not discriminate the modes then gets the network prediction as target and does not pull the network; with the weak network term of the forcing, its target would be the mean of its time, which flattens the network (θ attenuated by the reliability of the counts, ~0.5 on Semrau). A bad network does not lock in, unlike hard labels: such cells only slow its updates, and its precision κ_g falls with the residuals of the informative cells. The network is fitted on the expected modes under these posteriors (the cross-entropy being linear in its target, this is the expected loss over the posteriors), which are also the targets of the network term of the OT and of the stopping error. With `weight_network_distribution` > 0 (genes of more than two levels), the end-state term of the network fit and of the stopping error also contains, per (sample, time), Σ_i (σ_(i) − q_i)², the sorted predicted σ against the quantiles of the levels under the mean posterior of the cells (1-D Wasserstein-2, analytic gradient, no Sinkhorn): the expected modes are less spread than the levels when the counts discriminate them poorly, and this term keeps the spread of the network; the sparsity level (QUT) stays that of the cross-entropy alone. These targets start from the EMD basins: target = λ_n·basin + (1 − λ_n)·expected mode, λ_n decreasing linearly from 1 at the first iteration to 0 at `min_n_loops` (the EM started from the classification EM: at the first iteration the network term is absent, and the expected modes of the cells whose counts do not discriminate are the mean of their time, a flat network from which the EM would leave slowly). The initial proteins are those of the forcing mode of each cell, with bands per sample and mode index. On the test set, the calibrated costs give the EMD basins that force the trajectories and, by default, the posteriors and their expected modes.

**Burst frequency of the network model.** kon is always a sigmoid of a single regulatory input (one network): kon(P) = k_low + (k_high − k_low) σ(basal + Σ_j θ_j P_j), with k_low and k_high the lowest and highest modes of the gene. A gene with more than two modes keeps them all: intermediate modes lie on the slope of the sigmoid (unstable states). They are only used by the inference (protein trajectories and target modes of the network fit); every simulator (ODE, PDMP, PDMP with explicit mRNA) and every kon computed from the network only use the two extreme modes.

**Regulation functions and model learning (`model_learning_grn`, `model_learning_chrom`).** The regulation functions of the model are computed by a single module, `inference/sigma.py`, each with its own families. After every network fit, the edges with |θ| < `seuil_min_network_intensity` (proteins in units of their high mode) are set to 0: they are absent for every use of the network (trajectories, OT costs, basins, scores, simulations), whose evaluations of σ skip the zero edges, whatever the family; the next fit may bring them back. The GRN function σ is used by the whole inference (network fit, OT costs, alpha, filtering, stopping error) and every simulator; the free-running SDE fit uses its torch mirror. σ_j = ℓ_j(basal_j + Σ_g θ_gj φ_j(P_g)), with a link ℓ (logistic) and a transformation φ of the regulators chosen by the target j: identity (the sigmoid of a linear input, default model) or logarithm, φ(P) = P̄ log(1 + P/κ)/log(1 + P̄/κ) (Hill type, σ = A Π_g (1 + P_g/κ_g)^(c_g θ_gj)/(1 + A Π_g (…)), κ = `model_learning_kappa` × P̄, P̄ the protein level of the high mode); φ(P̄) = P̄ in both families, so that θ has the same units (change of the logit between 0 and the high mode) and the sparsity penalty treats them equally. With `model_learning_grn = True` (with `one_hot_probas = True`, the families are fitted on the basins and `'ce'` scores against them: the Q function of the classification EM), `fit_network` selects the family of each target among `model_learning_phi` × `model_learning_link` (default `['herbach']`: the Herbach type, saturating (0 at P_j = 0, θ_ij at saturation), with a Hill transition of coefficient m (of the target) around the threshold s_j halfway between the low and high protein levels of the regulator (lowest and highest modes of its mixture), self-regulation included as an edge like the others (the model of Herbach et al. imposes a Hill self-activation on every gene); one candidate per Hill coefficient m of `model_learning_herbach_m = [1, 2, 4]`, so that the selection learns the cooperativity m of each target (the reference model is the logistic of the promoter occupancy). The identity (`'identity'`, sigmoid of a linear input) is a candidate on request: on [0, P̄] it is within 0.09–0.14 of the Herbach type of m = 2, and beyond P̄ its unbounded input lets the tail of the proteins pull the logit linearly, while a binding site saturates. The Hill type log(1 + P/κ) (`'logarithm'`) remains a candidate on request: on [0, P̄] it matches the Herbach type of m = 1 within 0.04–0.08 (a Michaelis–Menten of half-saturation s ≈ P̄/2), and two indistinguishable candidates would share the targets at random. Its form is set by `model_learning_herbach_form`: `'approximate'` (default, family `herbach`), φ(P) = P̄ h(P/s)/h(P̄/s) with h(x) = x^m/(1 + x^m), linear in θ like the other families (θ times a Hill step: the model of Herbach et al. to first order in θ); `'exact'` (family `herbach_exact`), the thermodynamic model of Herbach et al., each regulator j entering the logit of target i through ψ(t_ij, x_j) = log((1 + e^t x_j^m) / (1 + x_j^m)), x_j = P_j/s_j, instead of θ_ij φ(P_j); the edge is parametrised by its effect at the high mode, ψ(t_ij, P̄_j/s_j) = θ_ij P̄_j, i.e. t = log((1 + x̄^m) e^(θP̄) − 1) − m log x̄ (`sigma.herbach_theta`), so that θ has the units of the other families and, at θ = 0, the derivative of the exact form is the feature of the approximate one (same QUT, ridge and L1 units); a repressor is bounded by θ P̄ > −log(1 + x̄^m) (only the bound fraction is repressed), below which σ no longer changes. The threshold of each edge of an exact target, s_ij, is therefore learned on its kept edges (|θ| ≥ `seuil_min_network_intensity`; `herbach_threshold_sd`, default 1: Gaussian prior of this sd on log s_ij around log s_j, s_ij ∈ [0.01, 2] × P̄_j) in the refinement of the network fits, jointly with the corrections of θ and the basals (the first fit and its QUT use the current thresholds; self-regulations keep s_j, as they keep their θ; geometric mean over the sub-samples, stored in `sigma_spec_grn[:, 6:]`, [target, regulator], and used by every later step, saved again after the refit of `refine_network_degradations` with `refine_theta_with_sde = False`): a lower threshold lifts the bound, up to m log(P̄/P_low) as s → 0, which strong repressions need (with s_j = P̄/2, the bound is −1.1, −1.6 and −2.8 for m = 1, 2, 4). The approximate form keeps s_j: linear in θ, its repressions are not bounded, and its threshold would mimic m (both set the contrast h(x_low)/h(x̄) of a bimodal regulator) and make its fit non-convex. Oracle (`projet_modellearning/oracle_threshold.py`, true proteins and σ, true support and m, 4 networks × 3 runs): on data of the exact form with thresholds drawn in {0.1, 0.2, 0.35, 0.5} × P̄, the learned thresholds recover the true ones (repressors: correlation of the logs 0.84, median error 3 %; activators: 0.62, 11 %) and the held-out KL to the true σ goes from 0.46 to 0.01 × 10⁻³ (median; mean 3.7 → 0.08); with s = P̄/2 they stay at P̄/2; on data of the approximate form (repressions −10), the exact form with learned thresholds reaches −4 to −7 instead of its bound but stays worse than the approximate form for every target (KL 34 vs 0 × 10⁻³), so that the form selection is not biased. ψ is nonlinear in θ: the network fit marks the inputs m log(P/s) of an exact Herbach target (`network.HerbachArray`, which carries m log x̄ and P̄ of its columns) and computes its logit and gradient in every term (end state, mRNA memory, flow matching, conditions, garrote); the scale of θ of the free-running fit multiplies θ inside ψ, as in the simulators); the first form of `model_learning_herbach_form` (default `['approximate', 'exact']`) is the base form, with which m is selected in a first window (one candidate per m); with a second form, a form window of the same length follows, in which each target compares its base family (m*) with the second form at m* (with `model_learning_form_neighbours = True`, default False, also at the neighbours of m* in `model_learning_herbach_m`: E1, E2 for m* = 1; E1, E2, E4 for m* = 2; E2, E4 for m* = 4), with the BIC term below for the learned thresholds; the current family of each target sets σ everywhere (trajectories, basins, simulations) in both windows; `sigma_selection.npz` holds the window of each selection (`window`, 0 base form, 1 form). Every target starts as the Herbach type of the m of the grid closest to 2 (the lower one on a tie; the first candidate without Herbach one), and keeps it until `model_learning_start` (default `min_n_loops`), while the targets ramp from the EMD basins to the posteriors and the trajectories settle; then, every `model_learning_period` iterations (default 1; > 1: in between, the network is refitted with the current families) until `model_learning_freeze` (default None: `model_learning_start` + 3; the families are then fixed and the loop converges with them; it stops only after the window and `model_learning_period` iterations after the last selection, with a warning if they end after `max_iter`), the network is fitted with every family on the same sub-samples (warm start from the last fit of each family), each target is scored on all the states by the mean fit of each family (σ along the mRNA memory with `targets_accounting_late_mrna`; the whole model is validated afterwards on the test set), with, for the exact form, the BIC term (k/2) log N / N of its k learned edge thresholds (kept edges, N states; `model_learning_threshold_bic`, default True), by the negative log-likelihood of the counts of their real cells under the network prior on the levels (`model_learning_score = 'marginal'`, default: −log Σ_l NB(x | k_l) p(l | σ), p(l | σ) ∝ exp(−κ KL(τ_l ‖ σ)) with the precision κ of the basin update, the likelihood maximised by the EM, to which a cell whose counts do not discriminate the levels contributes the same constant for every family; NB(x | k_l) read as π_l / w_l, posteriors of the mixture over the level masses of the time) or by the cross-entropy against the expected levels under the current posteriors (`'ce'`: the Q function of the EM, the family being a discrete parameter of the M-step; it favours the current family through the cells whose counts do not discriminate the levels, so that a target leaves its family only when the informative cells favour another one), and it changes family when another one is better by `model_learning_margin` at two consecutive selections; from `model_learning_freeze` on, the families are fixed. With a single link and a single φ (e.g. `model_learning_phi = ['logarithm']`), that family is forced for every gene from the first iteration and for the whole pipeline, without selection nor extra cost (fit and simulations with Hill functions). The result, `cardamomOT/sigma_spec_grn.npy`, is used by every later step (removed without model learning); `sigma_selection.npz` holds the scores and families of each selection. In the chromatin-gated burst frequency, k_low + (k_high − k_low) c̄ σ, σ is this GRN function. The opening function of the chromatin, σ_c in k_open = k̄ σ_c(Z^c) and k_close = k̄ (1 − σ_c(Z^c)), is a separate function of the same module, with its own families (`sigma_spec_chrom`, one per region); `model_learning_chrom = False` (default) keeps it logistic. Benchmark: `projet_modellearning/` (networks of the article with Herbach targets of m = 1, 2, 4), method note: `article/model_learning.tex`.

**Network fit and refinement (adaptive lasso).** For each target gene, the network is first fitted with an L1 penalty λ on the interactions (an edge of prior weight w costs 1/w more) and a Gaussian prior on the effect of each edge on the logit, w_e θ_e s_e ~ N(0, σ²) (s_e the standard deviation of regulator e over the states of the fit), σ = 2 logit(1 − 1/`network_ridge`): the logit span between a target at 1/`network_ridge` of its low mode and at 1/`network_ridge` of its high mode. The ridge bounds the edges of nearly separable targets (a gene almost always in the same mode), and its gradient vanishes at 0. λ is the quantile universal threshold (Giacobino et al. 2017): the target is permuted within each sample, the per-sample basals are fitted without interaction, and λ is the `qut_level`-quantile (over `qut_n_perm` permutations) of max_e |∂L/∂θ_e| at this null model, so that no edge enters a target without regulator with probability `qut_level` (KKT condition of the L1 at 0). It adapts to the number of states, of regulators, to their correlations and to the protein units. This gives θ̂. The refinement then fits multiplicative corrections c_e ≥ 0, θ_e = c_e θ̂_e, with the penalty λ'·Σ_e |c_e| (self-regulation and basals unpenalized). Since |c_e| = |θ_e|/|θ̂_e|, this is λ'·Σ_e |θ_e|/|θ̂_e| restricted to the support and signs of θ̂: the adaptive lasso of Zou (2006) with weights 1/|θ̂_e| (γ = 1), i.e. Breiman's non-negative garrote. With `network_relaxed = True` (default), λ' = 0: the refinement re-estimates the effects on the support and signs of θ̂ without the shrinkage of the L1 (relaxed lasso), within the same bounds and with the Gaussian prior of the first fit on the effects c_e θ̂_e (which bounds the edges of nearly separable targets, e.g. from a binary stimulus), so that the sparsity is set by the first fit alone and the shapes of the regulation functions are compared at their unshrunk effects (with the true burst frequencies of the benchmark, the shrunk effects send sigmoid targets to the Herbach type). With `network_relaxed = False`, weak first-stage edges are penalized more and removed, strong ones are less shrunk, and λ' is the quantile universal threshold of the garrote itself, θ̂ held fixed: the `qut_level`-quantile of max_e w_e (−∂L/∂c_e)₊ at the null model (c = 0 out of self-regulation, per-sample basals fitted), the target being permuted within each sample. Since ∂L/∂c_e = θ̂_e ∂L/∂θ_e, the level follows the shrinkage of the first fit, edge by edge. In the final fit of `refine_network_degradations` (`final` = 1), an L2 penalty towards the reference network is added to the L1 of the first fit (which keeps its level λ), and the bounds around the reference are lifted (signed priors only).

**Losses on the sigmoid.** Every network loss is a cross-entropy on σ, symmetric between ON and OFF: the target kon of a cell becomes τ = (kon − k_low)/(k_high − k_low) (0 at the lowest mode, 1 at the highest, between for an intermediate mode, a soft target that slightly smooths the sigmoid). This holds for the network fit (gene by gene, no weight), the network term of the OT cost and the stopping error (`count_errors`), where genes are summed with the weight w_g = 1 − k_low/k_high (0 when the two extreme modes coincide). The network term of the basin updates is the same cross-entropy, KL(τ_m ‖ σ), weighted by w_g.

**Continuous model of the counts (`max_grid_levels`).** With a mixture of two modes, σ is compared to the expected mode of each cell. A cell in a transient, at an intermediate burst frequency, is however read by the mixture {low, high} as high as soon as its counts are not zero: the expected mode is a concave function of the true σ, which flattens the network and biases the model learning towards Hill functions (`projet_modellearning/oracle_memory.py`). The mixture of each gene is therefore the **continuous model of the counts** (`max_grid_levels`): x NB of the burst frequency k_low + (k_high − k_low) σ (depth factor as in the mixture, `depth_model`), σ on K uniform levels of [0, 1] with weights per time, K chosen per gene by `mixture_selection_criterion` on the soft likelihood (`icl` by default, Biernacki et al. 2000: −2 log-likelihood + p log n + 2 × entropy of the posteriors; or `bic`) among grids of 2 to `max_grid_levels` levels (one mode is also a candidate with `min_mixture_components = 1`), each fitted from two starts (the extremes of the CEM + soft EM, and the `mixture_min_percentage` and 100 − `mixture_min_percentage` percentiles of the non-zero counts at the reference depth, default 5 %), the start of best likelihood kept for each K, the criterion being computed on these refined grids (`criterion_weights_per_time = False`: the level weights counted once, as the weights of the times are pulled together by their Dirichlet prior; `True`: once per time); `max_grid_levels = 2` gives two modes; the entropy penalises overlapping levels, so that a gene that switches keeps two modes (Dirichlet pseudo-count 0.01 per level, + 1 on the two extremes, which anchors k_low and k_high on occupied levels: without it, the extremes of a continuous model drift outwards with little mass), (k_low, k_high, c) and the weights fitted by EM (L-BFGS on the logarithms of the parameters, on the distinct (time, count, depth) triples) from the extreme modes of the CEM + soft EM, c at most 9, k_low at least min(c/2, k_high/100) as in the CEM (without this floor, the low level of a gene that is truly off goes to 0). Its levels are then the modes of the whole inference, with the same machinery as two modes: posteriors and basins (initial EMD under the weights of each time), forcing of the trajectories by the burst frequency of the level assigned to each cell, basin updates as posteriors on the levels combining the likelihood of the counts and the network term κ_g KL(σ_l ‖ σ) (for two modes, κ = 1 gives the Bernoulli prior p(ON) = σ; on the levels, exp(−KL) alone would be a flat prior of width ~σ(1 − σ), while a cell predicted at σ lies at the level σ: its precision κ_g is estimated per gene at each update by moment matching, mean σ(1 − σ) / mean E_q[(level − σ)²] (second moment under the posteriors updated by the network, the EM update of the precision; (level of the basin − σ)² with `one_hot_probas`), between 1 and `grid_network_precision_max` = 100, so that a gene well explained by the network gets a narrow prior and the others stay guided by their counts), network targets the expected level, i.e. E[σ | counts] updated by the network (the score of the model learning keeps the mixture alone). The cross-entropy is kept, so that the influence of each cell stays bounded. Two modes read the cells in a transient as part of the extremes, which pulls them inwards (the hard assignments of the CEM in addition truncate the overlapping modes: rate c overestimated, low mode too low); on the synthetic networks (k_low = 0, k_high/c = 100, c = 0.02), the continuous model gives 0, 94–98 and 0.020–0.021, and it fits the held-out cells of Semrau, Kameneva and Schiebinger better than two modes. On the test set, the levels are those of the training and the weights are re-estimated on the test cells.

**Logit-normal middle (`mixture_middle_nodes`).** With three modes, the middle level is a single point (σ = 1/2), while the cells in the middle of the regulation function have a spread of σ: their regulators vary, and σ is the logistic of their input. With `mixture_middle_nodes` = Q > 0 (and `max_grid_levels` ≥ 3), one more candidate is compared by `mixture_selection_criterion`: the two extremes and Q evenly spaced inner levels σ_q = q/(Q + 1) (a uniform grid of Q + 2 levels), whose weights at time t are π_low,t, π_mid,t w_q and π_high,t, with w_q ∝ φ((logit σ_q − μ)/s) / (σ_q(1 − σ_q)) the logit-normal density of the middle (μ, s common to the times, μ ∈ [−6, 6], s ∈ [0.1, 10]). It is fitted by the same EM, with the masses of the three modes under the Dirichlet prior of the grid and (μ, s) by L-BFGS on the expected counts of the inner levels; the criterion counts 2 masses + (μ, s) instead of K − 1 weights, and its entropy is that of the three modes (inner levels grouped). Its levels are levels of the whole inference, so that the cells of the middle get graded targets E[σ | counts] instead of the single middle level. The masses constrained in the assignments are those of the three modes only (low, middle, high; `_grouped_emd`, `_grouped_sinkhorn`): the shape being common to the times, masses per inner level would impose the same distribution of the middle at every time, while the cells of a transient drift through it. In the E-step (and the calibrated assignment of the test set), the cells are therefore distributed within the middle by the likelihood of their counts at each level (posteriors of the mixture over the level masses of their time) and the network term: EMD on the three modes at the lowest cost of each, the cell taking its best inner level, and entropic coupling on the three modes at the soft-min costs, split within the middle by exp(−cost); the initial basins (mixture alone) keep the posteriors of the mixture, shape included. Q is odd (an even Q is raised by one, with a warning), so that the point middle σ = 1/2 is among the inner levels and the comparison with it is nested. The middle is identifiable only when the NB of a burst frequency is narrow, i.e. for genes with a large shape k_high/d0 (many bursts per mRNA lifetime; the size of the bursts does not help): on the synthetic networks with shapes ×20 (k_high/d0 = 40), R² of the expected σ of the middle cells against the true one 0.75 → 0.87, while with their own shapes (k_high/d0 = 2) no model of the middle beats two modes. Q = 5 is within 0.02 nat/cell of a fine quadrature. The shapes (μ, s) are saved (`mixture_middle_shape.npy`, NaN for the other genes): on the test set, and for the pairs of samples classified with the reference parameters (integration), only the masses of the three modes are re-estimated, the middle keeping the shape of the training.

**Memory of the mRNA (`targets_accounting_late_mrna`).** The mRNA of a cell reflects its burst frequency over the last ~1/d0 hours, not at the time of the observation: M(t) = E[kon(t − U)], U ~ Exp(d0) (dM/dt = d0 (kon − M)), d0 being at least `min_ratio` × d1 (as in the bridges, the refine and the simulations). The burst frequency σ(P(t)) predicted by the network therefore leads the mRNA from which the modes are read: with `targets_accounting_late_mrna = True`, every comparison of σ with the mode of a cell compares what the mRNA shows of it. In the network fit (first fit, refinement, conditions, QUT), the stopping error, the basin updates and the score of the model learning, with `late_mrna_nodes = Q ≥ 2`, σ is averaged on Q regular nodes over the last min(interval, 5/d0) hours (d0 of the slowest gene), with the weights of the kernel d0 exp(−d0 (t − s)) of each target (trapezoidal rule, the mass before the window on the earliest node, the start state). Everything that evaluates σ many times (the network term of the OT, the free-running fit, kon^θ, the simulated counts, and the fit with `late_mrna_nodes = 1`) uses single lagged nodes instead: within an interval of length Δt, kon before its start being represented by the start state, the age of the kon read on the mRNA is V = min(U, Δt), and σ(P(t − E[V])) replaces E[σ(P(t − V))] (exact for σ(P) affine in time), with E[V] = (1 − e^{−d0 Δt})/d0 (1/d0 for a fast mRNA, Δt for a slow one). The lag depends on the target (its own d0, all its regulators being taken at that time): the targets are grouped into `late_mrna_classes` classes of equal sizes by d0, each with the mean lag of its genes, so that each target is compared at the lagged node of its class (cost × classes of a single node). The switch of the forcing (`inference_alpha`) is the commitment of the network, kon being σ(P): with the bridges (`mrna_bridge`) or the modes alone, the forcing is kon and the delay of the mRNA is in their dynamics (d0 of the bridge, d1_eff). With the adaptive shrinkage of the observed mRNA (`inference_mrnas_direct` without `mrna_bridge`), the forcing is the mRNA level and switches after the commitment by the delay of the step equivalent to the relaxation of the mRNA over the rest L of the interval (same integral, the step reaching the partially relaxed level): s = L (1/x − 1/(e^x − 1)), x = d0 L, at most L/2 and 1/d0 for a fast mRNA; the flow-matching nodes compare σ at their proteins with the kon in force there, which switches at the commitment, and the trajectories on the modes of the refine bring alpha back to it. The free-running fit of the refine (`refine_network_degradations`) compares the observed modes with the kon of the simulated proteins at the lagged nodes before each reached time (the d0 of `fit_network`: no gradient through d0 = d1/eps), the simulations themselves using the instantaneous σ(P(t)): the causal model stays instantaneous, only the observation of the modes accounts for the mRNA memory. Consistently, every kon read on the mRNA is taken at the lagged nodes: the kon^θ of the trajectories (`data_kon_theta.npy`, "Network" page, and the test trajectories, "Test" page, also with explicit mRNA) and the kon of the simulations from which the counts are drawn (protein-only simulations, and the ODE intervals with explicit mRNA; recorded per cell at Δt − lag of each class, resampled with the branching). The stored proteins stay those of the times of the states (they are the propagated states). The states without previous interval keep σ at the observation.

**Flow matching (`weight_flow_matching`, `flow_matching_nodes`).** The network fit adds, with weight `weight_flow_matching` (ramped from the second iteration to `min_n_loops`; the end-state term keeps 1 − this weight), the cross-entropy at `flow_matching_nodes` nodes of each interval between σ at the protein states there and the kon in force (mode of the start state before the switch alpha of the target, of the end state after it): the network reproduces the switching path, not only the end states. The nodes are deterministic, around the switch a of the state (mean of the alphas of the genes that change mode, weighted by the size of their change): the first just after it (a + 0.1, at a when a ≥ 1/2), then equally spaced on [0, a] and [a, 1] alternately from [0, a] (2: middle of [0, a]; 3: and of [a, 1]; 4: [0, a] at 1/3 and 2/3; …). The stopping error includes the flow-matching term with the same weight (the error the fit minimises), not the OT.

**OT cost of the trajectories.** Between a trajectory end and a real cell: w·A + (1 − w)·[(1 − 1/G)·B + (1/G)·P], with A = |Δ mRNA·s1|² (mRNA in kon units, as the modes and proteins: k_z/k1 at the mean of mode z), B the network term and P = |Δ protein|², A and P being brought to the median of B over the pairs of the batch (w and the weights are then true proportions); w decreases with the iteration while it is at most `intensity_prior`; with `intensity_prior` < 1, the first iteration has a zero cost (random couplings) and the network term alone is used afterwards. Both regularizations are relative to the cost of the batch: the cost is first taken relative to the best source of each target (C − min over the sources, so that no cell is dropped for being poorly explained by the network), and s, its median over the pairs (typical excess cost of a pair), sets the scale. The entropic regularization is `init_entropic_noise`·s·(1/n)^(1−1/n) at iteration n, divided by 10 at the last iteration only when `max_iter` < `min_n_loops` (the ramp of the regularization not completed); the test set (`infer_test`) uses the regularization of the last training iteration. The sharpness of the couplings thus depends neither on the scale of the cost (number of genes, normalization) nor on the improvement of the fit. Numerically, the cost of each source row is shifted by its minimum before Sinkhorn (its Gibbs kernel keeps an entry of 1: a row whose pairs all exceed ~745 times the regularization would otherwise underflow, stop Sinkhorn at an early iterate and leave the row empty, its trajectory then drawing the first cell of the batch); the plan is unchanged, the source masses compensating exactly (unbalanced: μ exp(c/reg_m), entropy relative to the original μν^T). The rare remaining failures (relaxed source marginal of the growth pass, non-finite plans) are solved again by a Sinkhorn in the log domain. The cost is not capped. The target marginal is enforced with the exponent f = reg_m/(reg_m + reg) of the unbalanced Sinkhorn, fixed at every iteration (also at the last one and for the test set) at its value for reg_m = u·s (u = `unbalanced_reg`) and the entropic regularization of `min_n_loops` (f ≈ u/(u + 0.19) with the default `init_entropic_noise`: 0.96 for u = 5, 0.98 for u = 10): reg_m follows the annealed entropic regularization, so that the relaxation does not vanish with it. No target is dropped for being poorly explained at the first iterations, since the cost is relative to the best source of each target. The relaxation only absorbs the uncertainty of the proliferation rates that correct the marginals (and lets `obs['lineage']` and `transition_rates` act): increase `unbalanced_reg` for more constrained marginals.

### Possible targets of the stimuli (`perturbation_inference`, row `all`, `STIMk`) — optional

`STIMk` of the row `all`: a gene list of `gene_lists` or comma-separated genes, k = column of `stimulus_inference_schedule`. Stimulus edges are then restricted to the listed genes: in the gene selection (Steiner selection anchored to the stimuli; the listed genes join the network universe) and in the network inference and simulation (`ref_network` stimulus rows set to 0 outside the list). A column naming no gene of the data means **no constraint** for that stimulus (not "no target").

## Multiple experimental samples (`dataset_id`)

If your experiment contains several biological conditions that share a gene regulatory network but have **different basal transcription rates** (e.g. different cell lines, donors, or perturbation backgrounds):

```python
adata.obs['dataset_id'] = ...   # string or integer label per cell
```

CardamomOT then:
- Builds one set of **per-sample basal parameters** `θ_basal(s)` for each sample.
- Runs a single joint optimisation over shared interaction weights and all per-sample basals simultaneously.
- Saves `basal.npy` with shape `(n_samples, G)`.

**Keeping per-sample basals close (`constrain_basal_uniform`):** set `model.constrain_basal_uniform = λ` (e.g. `λ = 100–1000`) to add an L2 penalty pushing each sample's basals toward their common mean. Genes with a non-zero `basal_ref` entry for a given sample (e.g. a KO prior) are excluded from the penalty for that sample.

### Network conditions (`network_condition`): one network per biological condition

Samples that are expected to be governed by **different regulatory networks** (naive vs tumour-bearing, wild type vs knockout line, untreated vs chronically stimulated) can be grouped into network conditions, a level above `dataset_id`:

```python
adata.obs['network_condition'] = ...   # one value per dataset_id (several dataset_id may share one)
```

With two conditions or more, each condition c has its own network θ_c = θ_shared + Δ_c, inferred jointly (fused lasso, as in joint graphical lasso / NetDes-Duo): the sparsity penalty applies to each condition network (weighted by its share of the samples, so that a common network costs as now) and an L1 penalty `network_condition_pen × sparsity penalty` applies to the deviations Δ_c − Δ_c^ref (in effective units: the literature prior weights the networks, not the deviations), with Δ_c^ref = inter_ref_c − mean over conditions of inter_ref_c: the mean reference constrains the shared network and the reference deviations constrain the deviations, so each condition network is pulled towards its own reference (Δ^ref = 0 without a per-condition reference: deviations pulled towards a common network). In `refine_network_degradations` the reference is the per-condition network of `fit_network` (or `inter_simul_ref`), whose differences are thus kept unless the data contradict them. The L1 makes most Δ_c exactly Δ_c^ref (values within 1e-2 of the median over conditions are fused), so an edge either keeps the reference deviations (shared without a reference) or is **rewired** in some condition; a sign change costs twice its magnitude.

- `network_condition_pen` (model_parameters sheet, default 1): large (≳ 10) = deviations equal to the reference ones (one common network without a per-condition reference); 0 = independent networks per condition; in between, an edge differs between conditions only if the data of a condition justify it about as much as a new edge.
- Basals stay per `dataset_id` (and `constrain_basal_uniform` still pulls all samples together, across conditions); schedules, KO/OV and `remove_from_inference` stay defined per `dataset_id`.
- The literature prior (`ref_network`, `inter_ref`) constrains every condition network (structure) and the shared one (reference / sign bounds); with `hard_forcing_ref` (fit_network) the deviations are pinned to the reference ones.
- Refinement: one multiplicative correction per edge, shared by the conditions (their differences are kept).
- A gene with a single mode in a sample (constant target) carries no information on its regulation there: as a target, that sample is left out of its network fit and of `constrain_basal_uniform`, and its basal is fitted alone on the final network. A condition where the gene has a single mode in every sample thus keeps the network set by the penalties (shared + reference deviations: edges present but inactive); as a regulator nothing changes (its constant protein is absorbed by the basals). This also holds without conditions (e.g. a KO sample for the KO gene).
- Outputs: `inter.npy`, `inter_simul.npy` are per sample `(n_samples, G, G)` (each sample with its condition's network; `inter_t*.npy` `(T-1, n_samples, G, G)`), `network_conditions.json` (condition of each sample), `inter_shared[_simul].npy` (median network over the conditions) and `network_differences[_simul].csv` (edges that differ, one column per condition, `sign_change`). Every step routes cells to their sample's network (OT, alpha, filtering, degradations, simulations, KO/OV, test, report: one GRN section per condition and a page of the differences).
- Without `network_condition` (or with a single value) nothing changes.
- **Genes per condition (`select_genes_per_condition`, default `False`).** With `True`, the genes are selected separately for each condition (`select_genes` on the cells of the condition, consensus of its samples, budget per condition), as if CardamomOT were run on each one: the data files hold the union, `uns['condition_genes']` = {condition: genes} (also `cardamomOT/condition_genes.json`), the selection report has a `condition` column and the network of the selection of each condition is `global_network_<condition>.npz`. A gene outside a condition is not modelled there: no mixture fit (a single mode), left out of the OT cost (mRNA and protein terms) and of the basin updates, neither target nor regulator in that condition's network, frozen in the simulations, its draws set to 0 in the stage files, and every comparison of that condition (classifiers, gene-pair correlations, embeddings) uses only its genes. The fused penalty (and the basal uniformity) only acts on what conditions share: an edge is fused between the conditions where both of its genes are selected (the shared network, the reference deviations and the fusion are taken over them), `inter_shared` and `network_differences` too. With `False`, every edge is shared and the penalty acts as before.
- **Refinement and proliferation per condition.** `degradation_rates_per_condition` (default `True`; former `condition_kinetics`): the network, d1, d0/d1 and the scale of theta are refined separately per condition, in `refine_network_degradations` and, with `refine_in_loop`, in `fit_network` (its samples and genes, its network as rappel, no fused term; rates stored per sample); `False`: one shared fit from the mean network of the conditions. `ProliferationMLP_per_condition` (default `True`): one proliferation MLP per condition on its trajectories and genes (`prolif_network_<k>.pt`, `prolif_network_conditions.json`), routed per cell in the simulations, the refinement and the report; `False`: one shared MLP. Both are forced to `True` with `select_genes_per_condition`.
- **Report.** With several conditions, the teasers (displacement fields on the common whole-transcriptome embedding, restricted to the cells of the condition), the classical OT and CardamomOT transitions, the generative model, the perturbations, proliferation, dilution, velocity fields, test and validation pages are drawn condition by condition, each on embeddings learned on its own cells and genes; the UMAP of every cell on the selected genes is drawn only when the gene space is common.

**Cell types per sample (random forest).** With several samples, the cell types of the simulated, reconstructed and test cells (report, KO/OV comparisons: `tools.characterize_cell_type`) are predicted by **one random forest per sample** (`dataset_id`), each trained on the observed cells of that sample — one classifier for all samples is too fragile, even after integration. Each cell is classified by the forest of its sample (the stage AnnData written by `check_sim_to_data` / `check_KOV_to_sim` carry `obs['dataset_id']`; older ones are labelled from `data_samples.npy`). A sample without a forest of its own (a sample held out of the inference, fewer than 50 cells or a single type) uses the one **indicated** by the `reference_sample` of `perturbation_inference` (also the sample whose cells start its validation simulation), else the one with the **closest name** (longest common prefix: `RMS2_ctrl` → `RMS2_trt`). A single sample keeps a single forest.


The report compares the condition networks (page "similarity between network conditions", `cardamomOT/network_similarity_<tag>.csv`), self-regulations excluded: cosine of the signed weights, Jaccard index of the signed edge sets (an edge is shared if non-zero with the same sign), and, as a function of k, the Jaccard index of the k strongest edges of two networks and the recall of the k strongest edges of one among the edges of the other. The table of differing edges also leaves out self-regulations.

### Per-sample mixtures and projection on a reference sample (`integrate_samples`, default False)

With two samples or more, `infer_mixture` assumes that **each sample identifies its own mixture modes (levels of the continuous model), but that the mRNA level of each mode may differ between samples** (capture efficiency, line, donor). The mixture is fitted on each sample alone (samples below `model.min_cells_integration = 200` cells are not), and the parameters are always kept per sample: `mixture_parameters.npy` is `(n_samples, M+1, G)`, samples ordered as `np.unique(obs['dataset_id'])`; every step routes cells to their sample's mixture (trajectory inference, network and degradation inference, simulation, NB sampling of the check scripts), each sample being normalised by its own maximal mode.

With `model.integrate_samples = True` (model_parameters sheet, or `--integrate-samples`), the counts of each sample are **projected on the reference sample** `model.ref_sample_integration` (a `dataset_id` value, or `--ref-sample <id>`; default: the first fitted sample). Each mode of a sample is sent on the mode of the reference that best explains its cells **taken as a whole**: the likelihood of the mean count of the group under the NB of the mode (mean and variance at the depths of its cells, divided by the size of the group), plus the log of the mass of the mode, the targets kept in the order of the modes. Cells grouped in a sample thus stay grouped in the reference, and the "ON" mode of a gene expressed only in another sample (the EM splits its zeros from its low counts) goes to the OFF mode of the reference instead of being lit (cell by cell, a broad ON mode explains each low count better than a near-zero OFF mode; it does not explain a whole group of them). With more than two levels, the rule acts on the two halves of the levels of the sample (σ ≤ 1/2, > 1/2), the candidates being the two halves of the reference (mixtures of their levels), a half going to the lowest or highest level; the levels are then carried linearly between the two targets, so that a difference of capture is corrected level by level (the rule level by level would send each level on the reference level of the same counts and undo the projection). Each cell, in the mode (level) of largest posterior in its sample, is then quantile-matched from the NB of that mode to the NB of its target (randomized quantile matching, counts stay integers), its posteriors, basin and the masses of its sample are carried to the targets, and every sample takes the parameters of the reference. `Data/data_{full,train,test}.h5ad` are then rewritten with the projected counts in `X` and the raw counts in `layers['counts_raw']` (a rerun always restarts from the raw counts). With `False` (default), each sample keeps its own fit and raw counts.

Pairs that are not projected, kept with raw counts and classified with the modes of the reference (posteriors and masses as a fit): the genes listed for a sample in sheet `perturbation_inference` (so that the perturbation stays visible against the reference level), the genes with a single mode in the reference (nothing to project on), and the cells of the unfitted samples. A gene expressed in a sample but not in the reference cannot be projected without losing its level: choose as reference the sample where the genes of interest are expressed. With `select_genes_per_condition`, a gene not active in the reference takes the first fitted sample where it is active as reference; genes active in no fitted sample take the pooled-fit parameters. Outputs: `mixture_parameters_samples.npy` (own fits) and `integration_report.csv` (per sample and gene: own, reference and used mode means, projected or not). With a single sample, nothing changes.

**Cell-type identity check** (`check_mixture_to_data`, report page "cell-type identity in the NB mixture", `cardamomOT/identity_mixture.csv`): one mixture draw per real cell is classified by per-sample classifiers trained on the other real cells (cross-fitting; a random forest and a logistic regression on log1p counts, both in the representation of `cell_depth_for_representation`, the forest relying more on fine co-expression), against two references: the real cells themselves (the classifier's own limit with these genes) and the real cells with the counts of each gene shuffled among cells of the same sample, time and mode (the best a model with these modes and genes independent given them can do). A drop real → shuffled means the modes are too coarse for that type; shuffled → draws, the NB fit.

Note that the projection removes level differences of the modes between samples, whether technical or biological; differences in mode *proportions* (which cells are ON) are kept, and are then explained by the per-sample basals.

## In-silico perturbation simulation (sheet `perturbation_simulation`)

After training, simulate arbitrary KO/OV combinations by defining them in:

| KO | OV |
|---|---|
| | |
| CHGA | STMN2 |
| POSTN | S100B,STMN2 |
| CHGA-80 | STMN2-60 |

(sheet `perturbation_simulation`; an empty row = wild type)

Each row produces one independent simulation saved as `cardamomOT/adata_sim_KO_*_OV_*_stim*.h5ad`.

**Partial KO/OV (`GENE-X` syntax):** append `-X` (0 < X < 100) for a partial perturbation of strength X%:

| Mode | Creation rate factor | Effect |
|---|---|---|
| `KO X%` | `× (1 − X/100)` | Reduced production → lower steady-state |
| `OV X%` | `× 1/(1 − X/100)` | Increased production → higher steady-state |

Output files use the `pctX` suffix to distinguish partial from complete perturbations (`KO_CHGApct80_OV_STMN2pct60`).

**Perturbation stimuli (`STIM1`, `STIM2`… columns, optional; `STIM` = `STIM1`).** Instead of genes forced from the start, a row can define new stimuli with their targets, each gene followed by `+` (activated) or `-` (inhibited): `CHGA+STMN2-` (or `CHGA+,STMN2-`; gene names containing `-` are recognised). On each target its effect is that of an interaction of ±(100 + the sum of the |interactions| received by the gene), which dominates them as a KO/OV does, multiplied by the value of the stimulus, which follows its column in sheet `stimulus_simulation_schedule` (column n_stimuli + k for STIMk; default 0 at the first time and 1 after) — e.g. a drug added at some time, or removed. Several stimuli add their effects, each with its schedule (e.g. two drugs given at different times); KO, OV and stimuli can be combined in a row; files are labelled `..._STIM1_CHGAup-STMN2dn`. The perturbed genes (KO, OV and stimulus targets) are always selected by the gene selection.

```
KO      OV      STIM1               STIM2
0       0       FTH1-FTL-NCOA4-     0
CHGA    0       STMN2+              VEGFA-
```

**Effects on the net proliferation rate (`RATE1`, `RATE2`… columns, optional; `RATE` = `RATE1`).** A drug acting on survival or division (not, or not only, on transcription) is given as `TARGET:delta` entries, comma-separated: `delta` (per time unit, e.g. `-0.01` for a death rate of 0.01 per hour) is added to the net rate R of a cell at the maximal score of `TARGET`, in proportion to its score, scaled by the value of perturbation stimulus k (same schedule as `STIMk`, which may be empty). `TARGET` is a gene list of the `gene_lists` sheet (any extra column, exported as `gene_list_<name>.txt`), genes joined by `+` (`FTH1+FTL+TFRC`), a gene, or `all` (every cell). The score of a cell is the mean over the genes of its protein level divided by the 99th percentile of the trajectories, clipped to [0, 1], evaluated along each simulated path as R. It acts in the branching simulation (proliferation MLP, `simulate_with_proliferation`; without the MLP the base rate is 0). The population size of each condition (`log` mean growth factor per interval, relative to t0) is saved (`data_log_population_<label>.npy`, `uns['log_population']`) and plotted in the overview of report section 3, the per-perturbation pages giving the population relative to WT at the last time; labels end with `..._RATE1_<target><delta>`.

```
KO      OV      STIM1                     RATE1
0       0       0                         iron_lysosome_high:-0.01
0       0       VEGFA-SLC2A3-PDK1-        iron_lysosome_high:-0.01,all:-0.002
```

## Literature degradation rates (`get_degradation_rates`)

`get_degradation_rates.py` writes per-gene mRNA (`adata.var['d0']`) and protein
(`adata.var['d1']`) degradation rates in **hour⁻¹** (`d = ln 2 / t½`, `t½` in hours, the time unit
of `adata.obs['time']`), together with their provenance (`d0_source`, `d1_source`), and a per-gene
report in `cardamomOT/degradation_rates_report.csv`. The reference tables ship with the package
(`CardamomOT/data/halflife/`, see its `README.md` for the sources and validation), so no network
access is needed.

**Species.** The organism is detected from the gene names — mouse (MGI) symbols such as `Gata1`,
human (HGNC) symbols such as `GATA1`, or Ensembl ids (`ENSMUSG…` / `ENSG…`). You can force it with the
parameter `species = 'mouse'` (or `'human'`) of the model_parameters sheet; the same value (or, when
`'auto'`, the same detection) is used by `get_proliferation_rates` and the literature prior.

**Reference half-lives.** Each species uses its own table:

| Species | mRNA | protein |
|---|---|---|
| mouse | Schwanhäusser et al. 2011 (corrected 2013), NIH3T3 — median 9.9 h | same — median 48 h |
| human | RNADecayCafe v1.1 (Vock et al. 2025), 11 cell lines — median 2.5 h | Mathieson et al. 2018, primary cells — median 81 h |

The two species are therefore not on the same absolute scale (different cell types and methods).

**Growth of the source cell lines.** The protein rates are pure degradation (Schwanhäusser subtracts
the dilution ln 2 / 27.5 h, eq. S4; Mathieson: non-dividing primary cells), but the mRNA rates are the
turnover of growing cell lines: metabolic labelling measures decay + dilution (fraction of old RNA
e^{−(kdeg + μ) t}; no growth term in Schwanhäusser eq. S7 nor in EZbakR). The growth rate μ of the source
lines is stored in `adata.uns['degradation_rates']['mrna_growth_rate']`: mouse ln 2 / 27.5 h = 0.025 h⁻¹
(NIH3T3, measured by Schwanhäusser), human 0.021 h⁻¹ (mean of ln 2 / T over the 11 RNADecayCafe lines,
doubling times from Cellosaurus). `d0` itself is the turnover; it is used as such with `mrna_dilution = False`.
Rates supplied in `adata.var['d0']` beforehand (no `d0_source`) are taken as pure decay (`mrna_growth_rate = 0`).

**Genes absent from the table** of their species are estimated, on that species' scale, from
their ortholog in the other species' table (linearly recalibrated on the orthologs measured in
both) and from biologically related measured genes: paralogs (weighted by protein identity), the
most specific HGNC gene family, and the genes with the most similar Gene Ontology annotation. The
weights of these sources are fitted by cross-validation on the measured genes; when nothing is
known (mostly lncRNAs) the median of the table is used. Gene names are matched through official
symbols, Ensembl ids, previous symbols and synonyms (e.g. `Hist1h4a` → `H4c1`, `OCT4` → `POU5F1`).

Rates are then clipped to [median/10, 10 × median] of the dataset. Existing `d0`/`d1` columns are
kept unless `overwrite_degradation_rates = True`, so you can supply your own rates in `adata.var` beforehand.

## Population dynamics: proliferation, death, and transition rates

### Net proliferation rate — default behaviour

CardamomOT only ever uses the *net* rate (birth − death), never the two terms separately, stored as:

```python
adata.obs['proliferation_net_rate']   # net proliferation rate per cell (birth − death)
```

**This is populated automatically, with no configuration needed.** Every run of
`get_proliferation_rates.py` (step "Proliferation rates" in the standard pipeline — the *first*
step, run before gene selection) estimates it from literature proliferation/death gene
signatures, following moscot's / Waddington-OT's approach (Schiebinger et al. 2019) — see
`CardamomOT/tools/estimate_proliferation.py`. It runs directly on `Data/data.h5ad` (all genes)
rather than after DE gene selection, since that filtering could otherwise discard many of the
literature marker genes needed to score the signature; because the rate lives in `adata.obs`
(per-cell), it is unaffected by the later gene-subsetting and train/test splitting done by
`split_dataset.py` / `select_genes.py`.

1. Each cell is scored against a proliferation gene set and a death gene set using
   `scanpy.tl.score_genes` (control-gene-bin corrected mean expression), on an internal
   total-count-normalised + log1p-transformed **copy** of the data — `score_genes` assumes that
   scale (moscot's own tutorials normalise/log-transform before scoring; moscot itself does not do
   it internally, it's left to the caller). The transformation is never applied to, or saved on,
   `adata` itself: CardamomOT's inference requires raw counts throughout, so only the resulting
   per-cell scores are kept — `adata.X` is read back unchanged afterwards.
2. Each score is mapped to a rate via the same shifted-logistic curve moscot uses:
   `rate(score) = rate_min + (rate_max - rate_min) / (1 + exp(-4/width · (score - center)))`,
   with moscot's own published defaults (verified against its source):
   `beta_max=1.7, beta_min=0.3, beta_center=0.25, beta_width=0.5` for birth, and
   `delta_max=1.7, delta_min=0.3, delta_center=0.1, delta_width=0.2` for death.
3. The net rate `beta(score_prolif) - delta(score_death)` is a **per-day** rate — like moscot/WOT
   themselves, whose `TemporalProblem` computes elapsed time from a `day` obs field and raises the
   per-timepoint growth score to that many days (`broadinstitute/wot`'s `OTModel.compute_transport_map`:
   `G = cell_growth_rate ** (t1 - t0)`, with `t0`/`t1` in days). CardamomOT instead expresses
   `adata.obs['time']` and every internal kinetic rate in **hours** (e.g. `NetworkModel`'s default
   degradation rates correspond to a 9h mRNA / 46h protein half-life), so it is divided by 24
   (`hours_per_day` in `estimate_growth_rates`) before being written to `obs['proliferation_net_rate']`
   — this makes it directly usable as `Δt` in hours in the OT-marginal correction below, with no
   further rescaling needed. Pass `hours_per_day=1` to `estimate_growth_rates` to recover the raw
   moscot-equivalent day⁻¹ rate if your own `adata.obs['time']` happens to be in days instead.

The marker gene lists are those of the species detected from the gene names (or given with
parameter `species`), copied verbatim from moscot's shipped defaults
(`moscot.utils.data.proliferation_markers`/`apoptosis_markers`): Tirosh et al. 2016 cell-cycle genes
for proliferation, MSigDB Hallmark Apoptosis for human death markers (MSigDB Hallmark P53 Pathway
for mouse — moscot does not use a symmetric death gene set across species).

`get_proliferation_rates.py` always (re)computes and overwrites `adata.obs['proliferation_net_rate']`,
even if that column is already present. If you have your own values (e.g. supplied from an external
measurement, such as EdU staining or a growth-curve-derived estimate) and want to keep them, skip the
step entirely instead: keep `estimate_proliferation_rates = False` (default; model_parameters sheet), or
uncheck **Proliferation rates** in `cardamomot run`.

Once populated, the OT marginals between consecutive timepoints t₁ and t₂ are modified:
- **Source marginal** µᵢ ∝ exp(+netᵢ · Δt/2) — cells with higher net growth carry more weight as trajectory sources
- **Target marginal** νⱼ ∝ exp(−netⱼ · Δt/2) — fast-growing cells at t₂ are down-weighted (they represent fewer distinct lineages)

This symmetric convention is CardamomOT's own: Waddington-OT and moscot weight the source by exp(net · Δt) and keep
the target uniform. Splitting the growth between both ends is the midpoint rule for the growth along the step,
more accurate when Δt is long.

### Birth, death and protein dilution (`protein_dilution`)

`get_proliferation_rates` keeps the **birth** and **death** rates of each cell separately (`obs['proliferation_birth_rate']`, `obs['proliferation_death_rate']`, net = birth − death; without stimulus: `obs['proliferation_*_rate_base']`), from the proliferation and death signatures (birth gated by senescence). Anchoring: the mean net rate of each cell type is set to its anchor (`proliferation_rates`, rates **without** stimulus, as corrected by `fit_population_anchors`), the signatures giving the heterogeneity within each type; the stimulus effects of `stimulus_rates` are added afterwards. A stimulus effect is a pure birth effect if positive (it then also dilutes the proteins) and a pure death effect if negative; its value per unit of stimulus k is kept per cell (`obs['proliferation_stimulus_birth_<k>']`, `obs['proliferation_stimulus_death_<k>']`). Every change of the natural net rate (anchoring) is shared between birth and death by the weight of birth in the cell, w = birth / (birth + death) (`estimate_proliferation.split_net_change`): a decrease lowers the birth by w |Δ| (down to 0) and the death absorbs the rest; an increase lowers the death by (1 − w) Δ (down to 0) and the birth absorbs the rest — birth, death ≥ 0 and birth − death = net. Without signatures, birth = max(net, 0).

The literature protein degradation rates d1 are **pure degradation** (Schwanhäusser: dilution subtracted with t_cc = 27.5 h; Mathieson: mostly non-dividing cells). With `protein_dilution = True` (default), the proteins of a cell are also diluted at its birth rate b (growth between divisions; `article/stationary_proliferation.tex`, eq. ode_dil): dP/dt = d1 u − (d1 + b) P = (d1 + b)(c u − P), c = d1 / (d1 + b), u the normalised transcriptional forcing (mode k_z/k1 along the inferred trajectories, kon(P)/k1 in the network model). In `fit_network`, a step between a source state and a target cell uses the birth rate of the real cell of the source before the switching time α of each gene and that of the target after it, as the modes: relaxation rate d1 + b and mode targets compressed by c = d1 / (d1 + b) on each side (protein steps, OT costs, switching times α, flow-matching states, timepoints missed by a sample, re-estimated trajectories); initial proteins at the compressed equilibrium. In each gene, the modes switch at its own α and the birth rate at `trajectory.birth_alpha` (exact step in three pieces): its own α if its mode changes, else the mean α of the genes that change (weighted by the change; 1/2 if none), i.e. at the time of the global change of state; α itself is never modified by it, and with the same birth rate at both ends the step is exactly the one without dilution switch. The refits of d1 and d0/d1, which have no α, use a birth rate linear in time from the start state to the end state. In the refine SDE and the simulations, the birth rate of each simulated cell is that of its nearest trajectory state at the start of each interval (mean of the birth rates of the state's two ends; `proliferation_mlp = False`, default; nearest state: see the branching simulation below), or with `proliferation_mlp = True` the birth head of the proliferation MLP at the simulated state (trained in `infer_network_simul` whenever `protein_dilution` or `simulate_with_proliferation` is set). Dilution is independent of `simulate_with_proliferation`, which only controls the selection (branching, population weights).

**mRNA dilution (`mrna_dilution`, default `True`, only with `protein_dilution`).** The observed mRNA is a concentration (counts relative to a transcriptome that scales with the cell volume), diluted by growth at the same birth rate b: dm/dt = bursts − (d0 + b) m. Its levels are observed: the modes k_z and the mixture are unchanged, the burst rate being k_z (d0 + b) (the levels of fast-dividing cells are not compressed, unlike the latent proteins). Only the relaxation of the mRNA changes, from d0 to d0 + b, wherever it appears: the mRNA bridges (rate of the source before `birth_alpha`, of the target after, as the protein rate), the memory of the mRNA (`targets_accounting_late_mrna`: lags, nodes and switch delay with the birth rate of each state; with the mean birth rate of the targets of a sample for the nodes shared by all the pairs of the OT and by all the cells of a sample in the free-running fit), the explicit mRNA of the free-running fit (`sde2`, memory filter) and of the simulations (`simulation_mrnas_direct`: decay d0 + b, burst rates × (d0 + b)/d0, s1 unchanged). The protein-only models (ODE, protein-only PDMP, d1_eff) are unchanged: their reduction already neglects terms of order d1/d0, of the order of b/d0. With `mrna_dilution`, `infer_network_structure` subtracts the growth of the source lines from the literature turnover, d0 = max(d0 − μ, 0), before the floor `min_ratio` × d1 (the learned d0 = d1/ε of the refine stays a pure decay rate, b being explicit, as d1): mouse median mRNA half-life 9.9 → 15.4 h, human 2.5 → 2.7 h.

After the inference (`infer_network_simul`, `refine_network_degradations`), d1, d0/d1 and the scale of theta are learned by the free-running fit of the simulation model (see *Kinetics of the simulations*), with the prior birth rate of each state along the starting trajectories and, along the simulated paths, the birth rate the simulations use, so that the pair (d1, b) is consistent: d1 is a pure degradation rate, the dilution being counted once, in the fit and in the simulations alike. In the simulations, the birth rate is that prior birth too: with `simulate_with_proliferation`, its regression on the state of each simulated cell (a small network trained with the proliferation MLP on the prior birth and death of the states, without the stimulus when its effects are given apart); otherwise the prior birth of the trajectory slot of each cell at the inference interval containing the simulated one (the slot following the cell through the resampling). The net rate R(P) of the MLP drives only the branching: fitted on the OT marginals, it also absorbs composition changes (e.g. a growing quiescent fraction under treatment), which are not division rates. In the simulations, each cell is diluted at its birth rate over each interval, evaluated at its start state with the MLP, else the mean of the prior birth of its slot at the start and end of the inference interval (PDMP: the protein flow decays at d1 + b, the bursts unchanged; ODE: rate d1 + b and target × d1 / (d1 + b)); the parts of the net rate from the RATE effects and the inference stimuli are shared between birth and death by the same rule as above.

### Refining proliferation rates

Five optional levers, from least to most involved:

**1. Species** — the built-in marker gene lists follow the species detected from the gene names
(`Mki67` → mouse, `MKI67` → human). To override the detection, set the parameter `species`
(`auto`, `human` or `mouse`; default `auto`) in the model_parameters sheet; it applies to
`get_degradation_rates` and the literature prior as well.

**2. Score on the unfiltered gene set** — if `Data/data.h5ad` was already prepared with a
pre-filtered gene set (e.g. by an upstream pipeline), the literature marker genes may be missing
from it entirely. Place the unfiltered dataset alongside it as `Data/data_complete.h5ad`:

```
my_project/Data/
├── data.h5ad            # gene-filtered — this is what gets updated
└── data_complete.h5ad   # full gene set — used only to score the signature, never modified
```

`get_proliferation_rates.py` detects `data_complete.h5ad` automatically and scores the
proliferation/death signatures on it instead of `data.h5ad`. The resulting per-cell rates are then
mapped onto the matching cells of `data.h5ad` by cell name (`adata.obs_names`) — every cell in
`data.h5ad` is assumed to also be present in `data_complete.h5ad` (the converse need not hold,
e.g. if `data_complete.h5ad` also contains cells later excluded by QC). `data_complete.h5ad` is
read-only from this script's perspective: only `Data/data.h5ad` is ever written to, and
`split_dataset.py` and `select_genes.py` (the next pipeline steps) only ever read `Data/data.h5ad` — it is
not aware of `data_complete.h5ad`. If `data_complete.h5ad` is absent, `data.h5ad` is used directly
for both scoring and output, as in the default behaviour above.

**3. Custom marker genes** — override the built-in lists entirely, e.g. for a disease- or
lineage-specific signature not well captured by the generic defaults (cell-cycle/apoptosis genes
are fairly conserved across contexts, but a cancer model with an altered p53 pathway, or a
lineage-specific death program, may warrant its own signature). Fill the columns
`proliferation_signatures`, `death_signatures` (and `senescence_signatures`) of the sheet `gene_lists`,
one gene per row (e.g. MKI67, TOP2A, CCNB2 / BAX, CASP3, FAS).

**4. Anchor to a known rate** — if you have a trusted population-level growth rate per cell type
(e.g. measured from a growth curve on sorted populations), fill the sheet `proliferation_rates`. Grouping uses
`adata.obs['cell_type_proliferation']` if present, else `cell_type_transition`, else
`cell_type` (if none is present, the unanchored estimate is kept) — add `cell_type_proliferation` during preprocessing if
you want a coarser or finer grouping for this task specifically, without touching `cell_type` itself:

| cell_type | net_rate_per_hour | sample_id | birth_rate_per_hour | death_rate_per_hour |
|---|---|---|---|---|
| TypeA | 0.10 | | | |
| TypeB | -0.02 | | 0 | |

Every cell type needs a net rate, given directly or as `birth - death`. The columns
`birth_rate_per_hour` / `death_rate_per_hour` are optional: with the net rate, one of them gives the other
(TypeB above: no division, death 0.02 h⁻¹); birth matters on its own because it sets the dilution of the
proteins.

The rate is per HOUR, matching `adata.obs['time']`, NOT moscot/WOT's day⁻¹ convention (see "Net
proliferation rate — default behaviour" above): divide a day⁻¹ growth-curve rate by 24.

No unit conversion is applied: the values are added directly to the
(already hour⁻¹) literature estimate via `combine_growth_rates_with_reference`, so a day⁻¹ value
left unconverted would be 24× too strong or too weak.

The literature-based per-cell estimate is then recentred, within each cell type present in this
sheet, so its mean matches the reference value exactly — while keeping the per-cell heterogeneity
coming from the gene signature. Anchoring is all-or-nothing: if any cell type of the data is
absent from the sheet, a warning lists them and all cells keep the raw (unanchored) literature
estimate, since a partial anchoring would bias the relative rates. Concretely, for a cell type `g`
with reference rate `r_g`:

```
final_rate[cell] = lit_rate[cell] - mean(lit_rate[g]) + r_g      for cell in g
```

the change of the net rate of each cell being shared between its birth and death rates in proportion to them
(`split_net_change`). For a cell type with reference birth `b_g` and death `d_g`, both are anchored
separately instead, each scaled to its reference mean (`anchor_birth_death`; rates are non-negative, so the
relative heterogeneity between cells is kept and a reference 0 gives 0 to every cell):

```
birth[cell] = lit_birth[cell] * b_g / mean(lit_birth[g]),   death[cell] = lit_death[cell] * d_g / mean(lit_death[g])
```

The anchoring is done **time by time** in each sample: the reference rates (without stimulus) are the mean rates of each
cell type at every time, the rates being constant in time apart from the stimulus effects (`RATEk`, value of the
stimulus over the interval that starts at the cell's time), added afterwards; in CardamomOT-stat (or without
`obs['time']`), all the cells of a sample are anchored together.

`fit_population_anchors` corrects the net rates on the proportions of the types; prescribed birth and death
follow the correction of their net rate, shared by `split_net_change`.

With `CardamomOT_method = 'stat'` (model_parameters), or automatically when `obs` has no `time`, each sample is
treated as a stationary snapshot (CardamomOT-stat): its times are ignored, and rates and transitions are corrected so
that the composition of the sample is the stationary (Perron) composition of the population model; population sizes,
if given, set its growth rate. Without any rate, transition rate or population size in the workbook, nothing is fitted.

**5. Full manual override** — set `adata.obs['proliferation_net_rate']` yourself and skip the
`get_proliferation_rates` step entirely (`estimate_proliferation_rates = False`, see
default behaviour above); the step no longer detects and preserves pre-existing values on its own,
it always overwrites them when run.

All of the underlying functions (`score_gene_sets`, `estimate_growth_rates`,
`combine_growth_rates_with_reference`) are also available as a public API for use outside the
CLI pipeline, e.g. in a preprocessing notebook:

```python
from CardamomOT import estimate_growth_rates, combine_growth_rates_with_reference

net = estimate_growth_rates(adata, species="mouse")
adata.obs['proliferation_net_rate'] = combine_growth_rates_with_reference(
    net, adata.obs['cell_type'].values, {"TypeA": 2.3, "TypeB": -0.1}
)
```

### Cell-type transition rates (sheet `transition_rates`) — opt-in

To bias the OT cost toward biologically plausible transitions:

| from \ to | TypeA | TypeB | TypeC |
|---|---|---|---|
| TypeA | | 0.02 | 0 |
| TypeB | 0 | | 0.01 |
| TypeC | 0 | 0 | |

(sheet `transition_rates`: rows = source type at t1, columns = target type at t2; off-diagonal entries = instantaneous transition rates ≥ 0 in hour⁻¹, 0 = no direct transition; the diagonal is ignored)

Row/column names must match `adata.obs['cell_type_transition']` if that column is present, else `cell_type_proliferation` (the grouping used for [proliferation rates](#anchor-to-a-known-rate)), else `cell_type`. The matrix defines a continuous-time Markov generator Q between cell types (diagonal = minus the row sum of the rates). At each pair of consecutive timepoints separated by Δt, the type-to-type transition probabilities are Π = expm(Q·Δt) (matrix exponential: indirect transitions, e.g. A → B → C, are accounted for). The entropic OT kernel exp(−C/ε) is multiplied by Π, i.e. the term −ε·log Π(type of source, type of target) is added to the OT cost. Transitions that cannot occur within Δt (Π = 0) get a factor 1e-12, which forbids them in practice while keeping Sinkhorn stable. With short intervals Π ≈ identity (cells mostly keep their type); with long intervals indirect transitions become possible. The constraint is all-or-nothing: if no grouping column is found, or any cell type of the data is absent from the matrix rows or columns, a warning is printed and the OT runs without any transition constraint.

### Clonal lineage constraint (`adata.obs['lineage']`) — opt-in

If `adata.obs['lineage']` is present (e.g. a clonal barcode from lineage tracing), the OT cost is
adjusted so that a cell only maps to a cell of the same lineage at the next timepoint: cross-lineage
pairs get a very large (but finite) additive penalty rather than being excluded outright, so Sinkhorn
stays numerically stable even when a batch happens to contain no same-lineage target — the constraint
degrades gracefully for that batch instead of breaking convergence. Cells with no lineage annotation
(NaN/empty) are left unconstrained. No CSV is needed — the barcode is compared cell-to-cell, not
aggregated by type.

## Simulation models (`simulation_stochastic`, `simulation_mrnas_direct`, chromatin regions)

Every simulation (`simulate_network`, `simulate_network_KOV`, validation of `infer_test`) starts from the first-timepoint states and routes each cell to its sample (basal, mixture, network condition, stimulus schedule, proliferation). The kon of gene g is k_low + (k_high − k_low) · cbar_g · σ(basal + Σ_j θ_j P_j), the lowest and highest modes in burst rate k·d0, with cbar_g = 1 without chromatin.

| `simulation_stochastic` | `simulation_mrnas_direct` | Model |
|---|---|---|
| 0 | — | ODE on the proteins (deterministic limit, mRNA at its mean) |
| 1 (default) | False (default) | bursty PDMP on the proteins (protein bursts, mRNA eliminated) |
| 1 | True | bursty PDMP with explicit mRNA: mRNA bursts of mean size 1/c at rate kon, dM/dt = −d0 M, dP/dt = s1 M − d1 P, s1 = scale · d0 d1 c / k_high (P ≈ `scale_proteins` in the highest mode) |

With explicit mRNA, the simulated mRNA are returned as counts (Poisson of the mRNA level, whose marginal is the NB of the modes), saved to `cardamomOT/data_mrna_simul.npy` and used directly by `check_sim_to_data` (no NB sampling). The simulator is adapted from the Harissa package (adaptive thinning on a bound of kon along the flow); it supports several stimuli, per-sample parameters, protein dilution and branching.

**Kinetics of the simulations (`refine_network_degradations`).** The simulation model is fitted **free-running** (no teacher forcing, `inference/sde.py`): from the trajectory states of a starting time, the model is integrated over the next intervals and compared at each reached time with the kon of the observed modes (debiased Sinkhorn per sample and time; with explicit mRNA also the observed mRNA, normalised as m = M c `scale_proteins` / k1), so that the errors accumulated along the simulations are corrected. Without `one_hot_probas`, the observed kon are levels drawn at every minibatch from the posteriors updated by the network (the Sinkhorn divergence compares distributions, which their mean would contract, unlike the cross-entropy of the network fit), the kon distances being in units of the total standard deviation of these levels per gene. For a gene of two levels, σ is the probability of the high mode, as in the network fit (Bernoulli prior): the simulated kon is then read as a Bernoulli draw of σ between k_low and k_high, the gradient going through σ (straight-through), so that the fit does not push σ to 0 or 1 to reproduce two-mode targets with a continuous kon. Horizon curriculum: windows of 1 interval first, then 2, … up to `sde_max_horizon` intervals (chunks of 10 timepoints), `sde_windows` window starts drawn at each step (all windows of a step integrated together); the windows start only at the observed timepoints of each sample (virtual states are copies) and their intervals are those between its observed timepoints, so that a sample observed at fewer timepoints than the others (e.g. another network condition) has fewer horizons, the longest ones taking its whole time course. The model is the one simulated: ODE (`simulation_stochastic = 0`), protein-only bursty PDMP, or explicit mRNA, with the dilution and the branching of the simulations; the bursts of each integration step are Gamma increments with the mean and variance of the compound Poisson of exponential bursts (positive and skewed as the bursts, reparametrised). Learned: d1, ε = d1/d0 and the scale of theta per target gene (per interval with `use_temporal_degradations`; scale only with `fit_scale_theta`, within [1/5, 5]), from the literature (ODE and protein-only PDMP: d1_eff = d0 d1/(d0 + d1) and d0/d1_eff = 1 + r; explicit mRNA: d1 and r = d0/d1), with an L2 rappel on their logarithms (`sde_lambda_rates`). The reference proteins are the unitary proteins (modes, literature d1_eff) for the ODE (`simulation_stochastic = 0`) without observed proteins only; for the stochastic models, and whenever `Data/data_prot.h5ad` is given (rescaled observed proteins, also for the ODE), the proteins of `fit_network` and its network are the references; for the protein-only bursty PDMP (`simulation_stochastic = 1`, `simulation_mrnas_direct = False`) with proteins reconstructed with the mRNA (`inference_mrnas_direct` or `mrna_bridge`) and without observed proteins, these proteins are first brought to the scale of the protein-only model by one factor per gene (`_rescale_trajectory_proteins`: the exact first moment d/dt E[P] = d1 E[u] − E[(d1 + b) P] of `_protein_scale`, as for observed proteins, with the forcing modes, the birth rates of the states and weights exp(−∫R_opt) along each trajectory, the trajectories being the lineages: no ancestor kernel), keeping their distribution. The windows start from them, and a proximity term compares, at the last time of each window, the simulated proteins with the reference proteins of that time (debiased Sinkhorn, per gene in units of their standard deviation, weight `sde_protein_weight` = 0.1 relative to the term on kon; 0: kon and mRNA only; not used for the ODE on observed proteins).
- `refine_theta_with_sde = True` (default): the network of `fit_network` is refined in the fit (support and signs kept, relative L2 rappel `sde_lambda_theta`), without refit.
- `refine_theta_with_sde = False`: ODE without observed proteins, the network is refitted (`final = 1`) on the unitary proteins, then fixed in the fit; otherwise, the network of `fit_network`, fixed.
With network conditions and `degradation_rates_per_condition` (default), d1, d0/d1 and the scale are learned per condition (one fit per condition) and stored per sample: `degradations_temporal.npy` (T−1, 2, n_samples, G), `ratios.npy` (T−1, n_samples, G); every simulation (KO/OV, test) routes cells to their sample's kinetics.

**Chromatin regions (`model.chromatin`, file `cardamomOT/chromatin_simul.npz`).** R regions, each a Markov chain on discrete accessibility levels (default [0, 1], `c_levels` (R, Kmax) NaN-padded from 0 to 1; `diploid`: two independent chains per region, c_r = mean of the alleles). A region opens at k_open = kbar_c σ(Zc) and closes at kbar_c (1 − σ(Zc)) (mirror) or at a constant rate `k_close_const`, with Zc = basal_c + Σ_g P_g inter_c[g, r] (rows = regulators, stimuli included); jumps between adjacent levels, normalised so that dE[c]/dt = k_open (1 − c) − k_close c. It gates the gene through cbar_g = Σ_r w[g, r] c_r (`w` (G, R), rows summing to 1, a gene without region keeps cbar = 1). The chains are always stochastic, simulated exactly along the protein dynamics (thinning, with the ODE as with the PDMPs). Each simulated cell carries its levels (initially open for the regions with basal_c > 0, else closed, or `c0`); the accessibility is saved to `cardamomOT/data_chrom_simul.npy`. The npz holds `w`, `basal_c`, `inter_c`, `kbar_c` and optionally `k_close_const` (NaN = mirror), `c_levels`, `diploid`, `c0`; the regions are not inferred yet.

## Proliferation-aware simulation (`simulate_with_proliferation`)

CardamomOT learns a net proliferation rate R = birth − death **as a function of the inferred protein state**, R(P), from the unbalanced optimal-transport couplings of the final trajectories, and can simulate with it.

### How it works

**1. Growth OT pass (`infer_network_structure`, always run).**
Once the inference loop has converged, the network is fixed and one extra OT pass is run on the final trajectories (same costs and batches as the last iteration; trajectories are not modified, and the growth estimate is not fed back into the network inference). At each interval t_k → t_k+1, following Waddington-OT:

- the source marginal (trajectory states at t_k) starts from the prior growth `exp(R_prior · Δt)` — from `adata.obs['proliferation_net_rate']`, or uniform if none is given (only relative rates are then learned);
- the target marginal (observed cells at t_k+1) is kept nearly hard, while the source one is relaxed (`model.growth_reg_source`, × log G, default 2): states whose neighbourhood at t_k+1 is over-represented gain mass, the others lose it;
- the log mass gain of each state, `log(N · row marginal)`, is shifted so that the population growth of the interval, `mean_n exp(·)`, equals the prior one (anchored by `fit_population_anchors` on the population sizes, if the sheet `population_sizes` is filled: they are used there only, not again here).

The rate `R_opt = log mass gain / Δt` of each trajectory state (NaN at the last time) is saved to `cardamomOT/data_R_opt.npy`, and the real cell behind each state to `data_traj_real_idx.npy`. `model.n_growth_iter` (default 1) repeats the pass with the source weights set to the row marginals (WOT growth iterations); more iterations amplify the per-state noise.

**2. Fitting R(P) along paths (`infer_network_simul`, `proliferation_mlp = True` only).**
The net growth of the states used after `infer_network_structure` is the R_opt of the growth pass (`data_R_opt.npy`) with `use_recomputed_proliferation = True`, else (default `False`) the prior rate of the real cell of each state (`obs['proliferation_net_rate']`, saved per state in `data_R_prior.npy`): targets of the MLP, birth and death of the states (dilution), test set and report; R_opt is then never used (the inference itself always uses the prior rates in its OT marginals).
In the spirit of unbalanced probability flow matching (Maddu, Chardès & Shelley 2026), R is not regressed on the noisy per-state values but on their integral along trajectories: each trajectory is interpolated across all timepoints (shape-preserving PCHIP on the recomputed protein levels), and a two-hidden-layer MLP (64 units, Tanh, standardised inputs) is fitted so that

```
∫_{t_k}^{t_k+1} R(P_n(s)) ds  ≈  R_opt[n, k] · Δt_k       (trapezoidal rule, model.n_growth_nodes = 5 nodes)
```

plus a total-mass term making the population growth of each interval, `log mean_n exp(∫R)`, match that of the targets (the pathwise least squares alone fit the mean *log* gain and would underestimate it; `lambda_mass` = 10, both residuals divided by Δt so that they are rates, and by the sd of the target rates so that the loss is dimensionless: the weight decay of Adam, 1e-4, would otherwise dominate squared residuals of rates ~1e-2 h⁻¹ and flatten R). The inputs are the inference stimuli of the interval (constant along it, those of its end timepoint, as in the simulation) and the proteins, `R(u, P)` (`model.prolif_uses_stimulus = True`; a stimulus constant over all intervals has no effect, its weights stay at zero). The output is scaled by the mean and sd of the target rates. A second small network regresses the birth and death rates of the states on the same inputs (birth of the dilution in the simulations), each rate with its own scale (its mean) so that the death, often ~10x below the birth, weighs as much in the loss. 20 % of the trajectories are held out: training stops when their loss has not improved for 50 epochs and the best weights are kept. The weights are saved to `cardamomOT/prolif_network.pt`, the fit quality (R² of the path mean rates on training and held-out paths, population growth per interval) to `prolif_network_diagnostics.json` (report section 4).

**3. Branching simulation (`simulate_network` / `simulate_network_KOV`), as in the refine SDE.**
The log weight of each simulated cell over an interval is its net growth along its own simulated path, and the N cells are resampled multinomially **within each sample** (no Poisson extinction at R ≈ 0, and per-sample basals stay consistent). With `proliferation_mlp = False` (default; no MLP trained), the net growth is that of the nearest trajectory state at the start of the interval, constant over it: the growth over its own interval, `R_opt[k, n]` (or the prior rate with `use_recomputed_proliferation = False`), the target the MLP would learn. The nearest state (the same for the birth rate; at the last inference time, its own birth and death, net = birth − death) is searched among the observed states (virtual ones excluded) of the cell's sample, at the same time in the refine SDE (`_fit_free_running`, also within `fit_network` with `refine_in_loop`, then on the prior rates) and at the inference time nearest to the start of the simulated interval in the simulations, by `match_distance`: `match_kon_weight` (default 0.9) × the L1 distance of the kon of the simulated cell to the forcing modes `kon_beta` of the trajectories (not the network kon of the observed cells) + (1 − `match_kon_weight`) × that of the proteins, each brought to its median (the same weight re-assigns alpha in `fit_network`, kon_beta against kon_beta, and in the test set). The stimulus is left out of the distance: when the simulated stimulus u differs from that of the interval of the nearest state u_ref, the effects (u − u_ref) δ of the inference stimuli on its real cell are added (`obs['proliferation_stimulus_birth_<k>']`, `obs['proliferation_stimulus_death_<k>']` of `get_proliferation_rates`, per unit of stimulus k). Every stimulus or RATE effect is a pure birth effect if positive (it then also dilutes the proteins) and a pure death effect if negative. With `proliferation_mlp = True`, R(u, P) of the MLP is re-evaluated on the simulated states at the quadrature nodes of every interval, the log weight being `∫ R(P(s)) ds`; when the inference stimuli are constant over the observed trajectory states while they have rate effects, the MLP cannot learn these effects: it learns the natural rates (targets without the stimulus effects, no stimulus input, `natural` buffer of the network), the refine SDE and the simulations adding the effects u δ of the real cell of the nearest trajectory state (same search). The refine SDE weights its simulated windows the same way.

**4. Reference of the simulation.** At every step, each trajectory draws its next state among the observed cells of the next time (target marginal of the OT nearly enforced), so the selection does not accumulate along the paths: the trajectory states (and the NB mixture / network stages computed on them) follow the observed composition at each time, the reference of the simulations with or without proliferation. Reweighting them by the growth of their paths (exp ∫R) would count the growth a second time (Copycat_RMS2trt: total variation to the observed cell-type composition 1.8 points for the raw states, 2.2 with exp ∫R_opt, 4.5 with exp ∫ of the prior rates). A page of section 4 compares the cell-type proportions of the data, of the trajectories and of the simulation (total variation to the data per time); a simulation without proliferation lacks the selection of the observed population.

### Pipeline usage

Set `simulate_with_proliferation = True` in the model_parameters sheet: `infer_network_simul` then trains the MLP, and
`simulate_network` / `simulate_network_KOV` use it (one parameter, so the three steps are always consistent).

```bash
cardamomot pipeline -i my_project
# or step by step
cardamomot step infer_network_simul  -i my_project --stimulus 1.0 --prior 1.0
cardamomot step simulate_network     -i my_project
cardamomot step simulate_network_KOV -i my_project
```

### Notes

- `simulate_with_proliferation` is **off by default**. `infer_network_structure` always runs the growth OT pass and saves `R_opt` — enabling it later has no cost (rerun from `infer_network_simul`).
- If `prolif_network.pt` is absent when the simulations run (`infer_network_simul` not rerun), they print a warning and fall back to standard simulation.
- scRNA-seq only identifies *relative* growth: the absolute level of R comes from the prior (zero mean growth if no prior), itself anchored on the population sizes by `fit_population_anchors` when they are given.
- The final PDF report (`report_results.py`, section 4) compares prior and learned rates per cell and per cell type, shows the implied population growth and the proteins driving R(P).
